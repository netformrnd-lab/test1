# 블로그 글 작성

CRM마케팅팀 **검색·오운드 담당자**가 매일 쓰는 도구입니다.
결과물은 **네이버 블로그에 그대로 복사해 붙여넣을 수 있는 형태**로 나옵니다.

## 1단계 — 기준부터 읽는다 (건너뛰지 말 것)

작업 시작 전에 반드시 아래를 읽습니다.

- `브랜드기준/01-브랜드-원메시지.md` — 이 브랜드가 하는 한 문장
- `브랜드기준/02-톤앤매너.md` — 문체, 금지어, 채널별 규칙
- `브랜드기준/03-페르소나.md` — 누구에게 말하는가
- `브랜드기준/04-고객여정맵.md` — 이 글이 어느 단계용인가
- `브랜드기준/05-콘텐츠-제작기준.md` — 발행 기준
- `브랜드기준/06-키워드맵.md` — 이미 잡아둔 키워드가 있는가
- `콘텐츠/블로그/` 안의 최근 글 3~5개 — **중복 방지**

`( 여기를 채워주세요 )` 로 남아 있는 항목은 **비어 있는 것**입니다.
비었다고 멈추지 말고, 상식적인 기본값으로 쓰되 **마지막에 "기준이 없어 제가 정한 것" 목록으로 보고**하세요.

## 2단계 — 필요한 것만 묻는다

사용자가 이미 준 정보는 다시 묻지 않습니다. 아래 중 **없는 것만** 한 번에 모아서 묻습니다.

| 필수 | 없으면 |
|---|---|
| 브랜드 | 물어봅니다 (기준 파일에 브랜드가 하나뿐이면 그걸로) |
| 주제 또는 키워드 | 물어봅니다 |
| 여정 단계 | 주제에서 추론하고 "이 글은 **비교** 단계용으로 잡았습니다"라고 알린 뒤 진행 |
| 페르소나 | 기준 파일에서 골라 쓰고 알립니다 |

**질문은 최대 한 번, 3개 이하로.** 사용자는 코드를 처음 다루는 마케터입니다.

## 3단계 — 원고를 쓴다

### 검색에 걸리게 하는 3가지 (한국 시장 기준)

**SEO — 네이버·구글 상위 노출**
- 제목에 핵심 키워드를 **앞쪽에** 넣습니다. 제목 30자 내외.
- 핵심 키워드는 본문에 **3~5회**, 억지로 반복하지 않습니다.
- 소제목(H2/H3)에 연관 키워드를 자연스럽게 넣습니다.
- 첫 100자 안에 핵심 키워드가 한 번 나옵니다.

**AEO — 질문형 검색에 직접 답하기**
- 소제목 중 최소 2개를 **질문 형태**로 만듭니다. (예: "OO 시공 비용은 얼마인가요?")
- 각 질문 바로 아래 **첫 문장에서 40자 이내로 직답**합니다. 설명은 그다음.
- 글 하단에 **FAQ 3개**를 넣습니다.

**GEO — AI가 우리 글을 인용하게 하기**
- 수치·연도·고유명사를 **문장 안에 명시**합니다. ("작년"❌ → "2025년"✅)
- 정의 문장을 하나 넣습니다. ("OO공법이란 ~를 말합니다.")
- 근거의 출처를 본문에 밝힙니다.
- 표 또는 번호 목록을 최소 1개 넣습니다. AI가 인용하기 쉬운 형태입니다.

### 글 구조

```
제목 (30자 내외, 핵심 키워드 앞쪽)

[도입 3~4문장]
- 첫 문장: 독자의 상황을 그대로 말해준다 (페르소나가 한 말 활용)
- 둘째~셋째 문장: 이 글에서 얻어갈 결론을 미리 준다
  ※ 검색으로 온 사람은 스크롤하지 않습니다. 답을 먼저 줍니다.

[소제목 1] 문제·배경
[소제목 2] 질문형 — 핵심 정보 (첫 문장 직답)
[소제목 3] 질문형 — 비교·기준 (표 1개)
[소제목 4] 우리의 해법 / 사례
  ※ 원메시지에서 벗어나지 않게. 여기가 브랜드가 나오는 유일한 구간.

[정리] 3줄 요약 (번호 목록)

[FAQ] 질문 3개 + 각 2~3문장 답변

[CTA] 딱 하나. 여정 다음 단계로 연결.
```

### 지켜야 할 것

- `02-톤앤매너.md` 의 **금지어를 절대 쓰지 않습니다.**
- `01-브랜드-원메시지.md` 의 **증거 항목에 없는 수치·인증·수상은 쓰지 않습니다.**
  필요하면 `[확인 필요: OO건]` 처럼 **대괄호 표시로 비워두고** 사용자에게 채우라고 알립니다.
  **절대 그럴듯한 숫자를 지어내지 마세요.**
- 이모지는 `02-톤앤매너.md` 가 허용한 경우에만.
- "~에 대해 알아보겠습니다", "결론적으로" 같은 AI 티 나는 문장 금지.

## 4단계 — 파일로 저장한다

`콘텐츠/블로그/YYYY-MM-DD-브랜드-키워드.md` 로 저장합니다. 파일 맨 위에 이 표를 넣습니다.

```markdown
| 항목 | 내용 |
|---|---|
| 브랜드 | |
| 여정 단계 | |
| 페르소나 | |
| 핵심 키워드 | |
| 연관 키워드 | |
| 예상 분량 | 0,000자 |
| 검수 | ⬜ 미완료 (`/cm-review` 실행 필요) |
| 발행일 | |
| 발행 URL | |
```

그 아래에 **① 복사용 본문**(블로그에 그대로 붙여넣을 텍스트)과
**② 발행 정보**(제목 3안 / 메타설명 80자 / 태그 10개 / 대표 이미지 아이디어 3개)를 넣습니다.

## 5단계 — 사용자에게 이렇게 보고한다

터미널에는 **길게 늘어놓지 말고** 아래만 알려줍니다.

1. 저장한 파일 경로
2. 제목 3안
3. **기준이 없어 제가 정한 것** (목록) — 사용자가 확인해야 할 부분
4. **`[확인 필요: ...]` 로 비워둔 곳** — 사용자가 사실을 채워야 할 부분
5. 다음 할 일: `/cm-review 콘텐츠/블로그/파일명.md`

## 절대 하지 않는 것

- 확인되지 않은 수치·인증·수상·순위를 지어내는 것
- 사용자를 대신해 블로그에 발행하는 것 (복사·붙여넣기는 사람이 합니다)
- `브랜드기준/` 파일을 마음대로 고치는 것 (제안만 하고, 반영은 사용자가 결정)
