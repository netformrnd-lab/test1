# 아파트스퀘어 영상 자동화

키워드 하나를 넣으면 프롬프트를 만들고, 헤이젠에 보내고, 완성된 mp4를 내려받는다.

```
npm run make -- "균열 3mm, 왜 기준이 되나" --trade 외벽 --len 180
```

```
out/20260907_균열_3mm_왜_기준이_되나/
  prompt.txt    보낸 프롬프트
  spec.json     장면 구성과 조건
  video_id.txt  헤이젠 작업 번호
  video.mp4     완성본
```

## 준비

Node 20 이상. 설치할 패키지는 없다.

```
cp .env.example .env
```

`.env` 에 헤이젠 API 키를 넣는다. 헤이젠 설정 → API 에서 발급한다.
웹 플랜 크레딧과 API 지갑은 별도이므로 API 지갑에 충전이 되어 있어야 한다.

## 처음 한 번: 엔드포인트 확인

**이 프로그램의 엔드포인트는 실제 호출로 검증되지 않았다.**
작성 환경에서 헤이젠 API와 문서에 접근할 수 없었기 때문이다.
아래 두 명령으로 계정에서 실제로 동작하는 값을 먼저 찾는다.

```
npm run check      키가 살아 있는지, 어떤 아바타·보이스를 쓸 수 있는지
npm run discover   어떤 경로가 열려 있는지
```

`discover` 결과에서 `← 후보` 로 표시된 POST 경로를 `.env` 의
`HEYGEN_CREATE_PATH` 에 넣는다. 상태 조회 경로도 마찬가지로 `HEYGEN_STATUS_PATH` 에 넣는다.

`check` 의 아바타 목록에서 한국인 아바타를 골라 `HEYGEN_AVATAR_ID` 에 넣는다.
이 값을 비워 두면 헤이젠이 임의로 고르고, 서양인 아바타가 나올 수 있다.

응답 본문의 필드 이름이 다르면 `src/heygen.js` 의 `create()` 와 `status()` 에서
`pick(...)` 에 후보를 추가하면 된다. 여러 이름을 순서대로 찾아보게 되어 있다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `npm run check` | API 키·아바타·보이스·잔여 크레딧 확인 |
| `npm run discover` | 열려 있는 엔드포인트 탐색 |
| `npm run prompt -- "키워드"` | 프롬프트만 만들어 출력 (호출 없음) |
| `npm run make -- "키워드"` | 프롬프트 → 생성 → 대기 → mp4 저장 |
| `node src/index.js status <video_id>` | 진행 중인 작업 상태 확인 |

옵션

```
--trade    외벽 | 옥상 | 지하 | 없음     공종 (기본 없음)
--audience 입대의 | 소장 | 입주민 | 시공사  대상 (기본 입대의)
--len      60 | 90 | 120 | 180 | 300    길이 초 (기본 180)
--dry-run  프롬프트만 만들고 호출하지 않음
```

## 무엇이 자동이고 무엇이 아닌가

자동

- 키워드 → 마스터 프롬프트 (장면 목록, 공종별 검증 수치, 등급표, 금지 사항)
- 헤이젠 생성 요청과 완료 대기
- mp4 내려받기

수동으로 남는 것

- **완성본 검수.** 같은 프롬프트로도 결과가 흔들린다. 장면 수, 화면 여백, 수치 표기를
  사람이 확인해야 한다. 검수 없이 올리면 사고가 난다.
- **사진·영상 소재.** 헤이젠에 직접 올린다. 프롬프트가 파일명으로 지정할 수는 있지만
  업로드 자체는 이 프로그램이 하지 않는다.
- **유튜브 업로드.** 아직 붙이지 않았다. YouTube Data API v3 + OAuth 리프레시 토큰으로
  `videos.insert` 를 호출하면 되고, 예약 공개도 API로 지정할 수 있다.

## 프롬프트 규칙을 고칠 때

`src/prompt.js` 한 곳에 모여 있다. `prompt-studio.html` 과 같은 규칙이므로
둘 중 하나를 고치면 다른 쪽도 같이 고쳐야 한다.

공종별 수치와 등급표는 `src/trades.js` 에 있다. 결과보고서에서 나온 값이라
새 공종이 생기면 여기에 추가한다.

## 비용

헤이젠은 생성된 초 단위로 과금한다. 실패한 렌더에도 과금되므로
프롬프트가 안정되기 전에는 `--dry-run` 으로 내용을 먼저 확인하는 편이 낫다.
