# 아파트스퀘어 — 하네스 연결 기능 · AI 직원 역할안

작성 2026-11-24 · 서비스운영본부 · 대시보드 미수금 관리 탭 도입과 함께 정리

## 1. 전제

- **하네스** = Claude Code 예약 작업(스케줄)과 세션. 저장소(GitHub)와 Supabase(DB), Cloudflare(배포)에 접근해 "데이터를 읽고 → 판단하고 → 초안을 쓰거나 기록하고 → 필요한 것은 사람 승인 뒤 실행"합니다.
- 콘솔 화면의 알림(회수 확인 D+7/D+14, 일정 없음, 담당 미배정 등)은 화면이 열릴 때 계산됩니다. 하네스는 **화면을 열지 않아도** 같은 규칙으로 데이터를 보고 담당자에게 알려주고 초안을 만들어 두는 역할입니다.
- 원칙: **돈이 움직이거나 외부로 나가는 일(메일 발송·입금 완료 처리·현장 삭제·배포)은 사람이 누릅니다.** AI는 점검·요약·초안·기록까지.
- 비밀값(Supabase service_role, 잔디 웹훅, Cloudflare 토큰)은 하네스 환경의 secret에만 두고 코드·문서에 넣지 않습니다.

## 2. 하네스로 자동화하면 좋은 기능 (우선순위순)

| 순위 | 기능 | 언제 | 읽는 것 | 하는 것 | 사람이 하는 것 |
| --- | --- | --- | --- | --- | --- |
| 1 | **회수 확인 일일 요약** | 매일 09:00 | receivable_items, site_contracts | 오늘 해야 할 1차/2차 확인·메일·전화·재확인·보류 재확인을 현장별로 묶어 잔디(또는 메일)로 요약 | 계좌 검색, 체크 |

| 5 | **감리일지 지연 알림** | 매일 09:00 | reports, apartments | 공사중 현장 중 최근 일지 10일(주의)/21일(지연) 초과 현장을 담당 감리원에게 푸시·잔디 | 방문·일지 작성 |

| 8 | **체크리스트 기한 리마인드** | 매일 09:00 | site_contracts.checklist, 단계 | 착공서류 요청 후 7일 미회신, 준공처리 후 잔금 미청구 등 "다음 할 일"이 멈춘 현장 알림 | 처리 |
| 9 | **NPS 회신 취합** | 금요일 | NPS 조사표 회신(메일·우편 입력), surveys | 회신·미회신 현장 목록, 미회신 전화 리스트, 의견을 개선 과제로 분류 | 전화, 과제 결정 |
| 10 | **월간 운영 보고 초안** | 매월 1일 | 전체 | 준공 실적, 미수금 회수율, 일지 주기, NPS를 표로 정리한 보고 초안(워드·슬라이드) | 검토·보고 |

## 3. AI 직원 역할 (가칭)

각 직원은 하네스의 예약 작업 1~3개로 구성됩니다. "승인 지점"이 사람이 반드시 누르는 곳입니다.

### ① 수금 담당 — AR 매니저
- 담당: 위 표 1·2·3·4
- 트리거: 매일 09:00 요약 / 2차 미입금 체크 이벤트 / 금요일 리포트
- 읽기: receivable_items, receivable_notes, site_contracts, apartments, message_templates
- 쓰기: receivable_notes(초안·제안 메모, team=ops), 리포트 파일
- 승인 지점: 메일 발송, 입금 완료 처리, 보류 전환
- 성과 지표: 미수금 회수율, 청구 후 입금까지 걸린 일수, 알림 당일 처리율

### ② 운영 점검 — 현장 코디
- 담당: 5·6·8, 관제센터 "확인할 현장" 요약
- 트리거: 매일 09:00, 월요일 09:00
- 읽기: apartments, reports, schedules, control_sites, site_contracts.checklist
- 쓰기: site_notes(현장 메모), 푸시/잔디 알림
- 승인 지점: 없음(알림만). 단계 변경·담당 배정은 사람
- 성과 지표: 일지 지연 현장 수, 일정 없음 현장 수, 체크리스트 멈춤 일수

### ③ 서류 담당 — 문서 어시스턴트
- 담당: 시공사 착공서류 요청 메일 초안, 준공완료보고서 구성 체크(필수 자료 누락), 안내문구 관리, 계약서 PDF 금액 읽기 검증
- 트리거: 체크리스트 "착공서류" 단계 진입, 준공처리 단계 진입
- 읽기: site_contracts, contracts(파일), specs, message_templates
- 쓰기: 메모·초안, 누락 체크 결과
- 승인 지점: 메일 발송, 보고서 발송

### ④ 영업 연결 — 파이프라인 지킴이
- 담당: 7, 구글시트 동기화 이상 탐지(단계 되돌림 시도·이름 불일치), 성사 딜 → 현장 연결 확인
- 트리거: 매일 10:00
- 읽기: sales_leads, apartments, control_sites
- 쓰기: 점검 결과 메모, 잔디 알림
- 승인 지점: 현장 병합·삭제, 성사 처리

### ⑤ 고객 경험 — NPS 담당
- 담당: 9, 입주민 앱 만족도(surveys)와 NPS 조사표 회신 통합
- 트리거: 금요일
- 읽기: surveys, NPS 회신 입력(콘솔 입력 또는 시트)
- 쓰기: 회신 현황, 개선 과제 목록
- 승인 지점: 전화, 과제 채택

### ⑥ 배포·품질 — 릴리스 봇
- 담당: 11, PR 테스트(목 데이터 브라우저 테스트·빌드 가드), 전후 비교 캡처, 변경기록 누락 확인
- 트리거: PR 생성·main 병합
- 읽기/쓰기: 저장소
- 승인 지점: PR 병합, 운영 배포

## 4. 구축 순서 (제안)

1. **1차 (2주)**: AR 매니저(일일 요약 + 정산 메일 초안) · 릴리스 봇(테스트·빌드·배포). 미수금 탭이 막 생겼으니 여기서 효과가 가장 큼.
2. **2차 (1개월)**: 현장 코디(일지 지연·일정 없음·체크리스트 리마인드) · 파이프라인 지킴이.
3. **3차**: 문서 어시스턴트 · NPS 담당 · 월간 운영 보고 초안.

## 5. 준비할 것

- 하네스 환경 secret: Supabase service_role 키(읽기·쓰기), 잔디 웹훅 URL, Cloudflare API 토큰(배포용)
- 알림 채널 결정: 잔디 토픽(운영본부 / 경영지원팀 / 감리원) 또는 이메일
- 경영지원팀 입력 경로: 콘솔 미수금 탭에서 직접 체크(권장) 또는 공유 엑셀을 하네스가 읽어 제안
- 네이버 메일은 API가 없으므로 메일은 초안까지만, 발송은 사람이 (안내문구 "메일용 복사" 유지)

## 6. 콘솔 쪽에서 이미 준비된 것 (2026-11-24 기준)

- 미수금 관리 탭: 계약 건마다 청구 항목(계약금·잔금, 과거 현장은 중도금 포함) 자동 생성, 청구 요청일 기준 D+7 1차 확인 → D+14 2차 확인 → 정산 요청 메일 → +3일 전화 확인 → 주 1회 재확인 알림, 운영본부·경영지원팀 체크와 메모, 엑셀 내보내기
- 관제센터 2단계 카드와 "회수 확인" 탭, 공사관리 목록 미수금 열의 D+n 배지, 현장 상세의 "청구·입금 관리" 바로가기
- 안내문구 "정산 요청" 템플릿({청구항목}{청구금액}{청구일}{발행일})
- 이 규칙은 콘솔 코드의 `arAlerts()` 한 곳에 있어 하네스도 같은 규칙으로 계산하면 됩니다(`backend/migration-receivables.sql`의 표 구조 참고).
