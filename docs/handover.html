🧱

어떻게 만들었나 — 기술 구조

특별한 프레임워크 없이 순수 HTML·CSS·JavaScript + Supabase 로 만들었어요. 서버 코드는 거의 없고, 보안·권한은 데이터베이스(RLS) 가 담당해요.

🖥️ 프론트엔드
프레임워크 없는 화면전환식 SPA(화면마다 id로 전환). 통합 앱 app/index.html + app/js/supabase-app.js, 관리자 app/console/index.html, 현장점검 app/inspect/, 견적·계약 app/control/.
🗄️ 백엔드 · Supabase
Postgres + 로그인(Auth) + 파일저장(Storage) + 실시간(Realtime). 공개키(publishable)는 코드에 넣어도 안전 — 실제 보안은 RLS 권한 규칙이 담당(is_admin() 함수로 관리자 판별).
🔑 역할 · 권한
회원마다 역할 profiles.role = admin·auditor·manager·resident. 역할에 따라 볼 수 있는 데이터가 자동으로 달라져요(입주민=우리 단지, 감리사=담당 단지, 관리자=전체).
🚀 배포
코드 = build-deploy.js 로 dist-deploy 만들어 Cloudflare 업로드. 데이터 구조 변경 = backend/*.sql 을 Supabase에서 실행. 앱 = Capacitor로 스토어 배포.

이어서 개발·배포하는 법

다음 사람이 코드를 수정해 반영하려면 이 순서예요.

코드 받기
GitHub netformrnd-lab/test1 를 클론(또는 Claude Code에 주소를 주고 수정 요청).
화면 찾기
고칠 화면의 파일을 연다 — 앱 app/index.html·app/js/supabase-app.js, 관리자 app/console/index.html, 현장점검 app/inspect/.
데이터 구조가 바뀌면 SQL 먼저
새 컬럼·표·권한이 필요하면 backend/*.sql 을 Supabase → SQL Editor에서 실행. 재실행해도 안전하게 작성돼 있어요.
빌드 → Cloudflare 업로드
node build-deploy.js 로 dist-deploy 를 만들고 그 내용을 Cloudflare에 업로드하면 앱·콘솔이 한 번에 갱신돼요.
앱(스토어) 갱신은 별도
안드로이드·iOS 설치앱은 Capacitor로 다시 빌드해야 반영돼요(웹은 즉시).
💡 핵심 원칙 — ① 모든 화면은 같은 Supabase 하나를 공유해 실시간으로 이어져요. ② 보안은 코드가 아니라 DB 권한(RLS) 이 담당해요. ③ 배포는 코드=Cloudflare, 데이터구조=SQL 로 나뉘어요.
📌 지금 상태 — 위 작업은 모두 브랜치에 커밋·푸시 완료. 회의에서 서비스 구성 변경 / 표기(동사·명사) 통일 / 문구 톤이 정해지면 그 기준으로 일괄 다듬을 예정.
아파트스퀘어 인수인계 · 개발 흐름 + 구조 + 이어가는 법. 세부 코드·권한은 app/, backend/*.sql 참고.
