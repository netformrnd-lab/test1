# 경영지원팀 업무관리(세금계산서) ↔ 아파트스퀘어 대시보드 연동 요청

작성 2026-11-25 · 서비스운영본부 · 전달용

## 1. 하려는 것

- 아파트스퀘어 감리 현장의 **계약금·잔금 세금계산서 발행 요청**을 운영본부 대시보드에서 버튼으로 올리면, 경영지원팀 업무관리 시스템(sq-biz)의 **발행 요청 목록에 자동 생성**됩니다.
- 경영지원팀이 **발행완료** 처리하거나 **입금 매칭**을 하면, 그 결과(발행일·발행금액·입금일·입금액)가 운영본부 대시보드의 **미수금 관리 탭에 자동 반영**됩니다.
- 운영본부는 계좌 검색이나 수기 확인 없이 미수금을 관리하고, 경영지원팀의 업무 방식(요청 목록에서 검토 → 발행, 입금 매칭)은 **지금과 동일**합니다.

## 2. 요청드리는 것

### (1) Firebase 서비스 계정 키 — 프로젝트 `sq-biz`

| 항목 | 내용 |
| --- | --- |
| 만드는 곳 | Google Cloud 콘솔 → 프로젝트 `sq-biz` → IAM 및 관리자 → 서비스 계정 → **서비스 계정 만들기** |
| 계정 이름(예) | `aptsquare-sync` (아파트스퀘어 대시보드 동기화 전용) |
| 역할 | **Cloud Datastore 사용자** (`roles/datastore.user`) — Firestore 읽기·쓰기. 소유자/편집자 권한은 필요 없습니다. |
| 키 | 만든 계정 → 키 탭 → **키 추가 → 새 키 만들기 → JSON** 다운로드 |
| 간단한 방법 | Firebase 콘솔 → 프로젝트 설정(톱니) → 서비스 계정 → "새 비공개 키 생성"도 됩니다. 단 이 키는 관리자 권한이라 위 전용 계정 방식을 권장합니다. |
| 전달 방법 | **메신저·메일 첨부 금지.** USB 또는 사내 보안 공유로 전달해 주세요. |
| 보관 | 운영본부 Supabase의 비밀값 저장소에만 보관. 코드·문서·채팅에 기록하지 않습니다. |
| 중단 | 콘솔에서 해당 서비스 계정 또는 키를 삭제하면 연동이 즉시 끊깁니다. 언제든 경영지원팀이 끊을 수 있습니다. |

**이 키로 하는 일의 범위 (이 외에는 손대지 않습니다)**

| 데이터 | 읽기 | 쓰기 | 용도 |
| --- | --- | --- | --- |
| 발행 요청 (taxInvoiceRequests) | O | **생성만** | 우리 쪽 청구 요청을 올리고, 발행완료·반려·보류 상태와 발행일을 가져옵니다. 기존 요청의 수정·삭제·상태 변경은 하지 않습니다. |
| 계약 (contracts) | O | 생성만 | 첫 청구 때 계약을 만들고, 이후 잔금 요청을 같은 계약에 연결합니다. |
| 입금 내역 (deposits) | O | X | 매칭된 입금의 날짜·금액을 가져옵니다. |
| 거래처 별칭 (partnerAliases) | O | X | 거래처 이름 매칭에 참고합니다. |

- 서비스 계정은 Firestore 보안 규칙과 별개로 동작하므로 **기존 로그인 방식이나 보안 규칙을 바꿀 필요가 없습니다.**
- 모든 자동 생성 요청에는 요청자 `아파트스퀘어 대시보드(담당자 이름)`와 요청 경로가 표시되어 사람이 올린 것과 구분됩니다.

### (2) 함께 확인·결정해 주실 것

1. **자동 생성 요청 수용 여부** — 운영본부가 대시보드에서 누르면 요청 목록에 바로 올라옵니다. 검토·발행은 지금처럼 경영지원팀이 합니다. 괜찮으신지요.
2. **발행 대상 거래처** — 아파트스퀘어 감리 계약은 현장에 따라 시공사 또는 입주자대표회의(아파트)와 맺습니다. 요청 폼의 거래처(상호·대표자·사업자번호·주소·업태·종목·이메일)는 **계약 상대방** 기준으로 채우면 되는지 확인 부탁드립니다.
3. **사업자등록증** — 같은 거래처의 두 번째 현장부터는 생략해도 되는지(기존 계약에 연결된 요청은 생략 가능해 보입니다). 첫 요청에는 운영본부가 보관 중인 사업자등록증을 함께 넣습니다.
4. **계약서 첨부** — 운영본부 대시보드에 올라가 있는 계약서 PDF를 그대로 첨부합니다(파일당 10MB 이하).
5. **청구 구분** — 요청 폼의 계약금 / 중도금 / 잔금 / 계약금+잔금 한 번에 선택을 우리 쪽에서도 같은 선택지로 보냅니다. 앞으로 신규 계약은 계약금·잔금만 있고, 중도금은 과거 현장에만 있습니다.
6. **잔디 알림** — 사람이 요청할 때 가는 잔디 알림을 자동 요청 때도 같은 토픽으로 보내려면 웹훅 주소가 필요합니다. 공유 가능한지, 또는 알림 없이 목록만 올릴지 알려 주세요.
7. **샘플 데이터** — 필드 확인용으로 최근 발행 요청 2~3건, 계약 2~3건을 내보내기(또는 화면 캡처)로 주시면 매핑을 정확히 맞출 수 있습니다. 금액은 가리셔도 됩니다.
8. **시범 운영** — 현장 2~3곳으로 1~2주 시범 후 전체 적용합니다. 시범 기간의 자동 요청은 제목에 `[시범]`을 붙이겠습니다.

## 3. 연동 후 흐름

1. 운영본부: 미수금 탭에서 **청구 요청 · 계약금(또는 잔금)** 클릭
2. 10분 안에 경영지원팀 요청 목록에 거래처 정보·사업자등록증·계약서·금액이 채워진 요청 생성 (+ 잔디 알림)
3. 경영지원팀: 지금처럼 검토 → 세금계산서 발행 → **발행완료** 처리
4. 발행일·금액이 운영본부 대시보드에 자동 반영. 반려·보류면 사유와 함께 "보류"로 표시
5. 입금이 입금 내역에 매칭되면 운영본부 쪽 입금일·금액 자동 반영, 회수 알림 자동 종료
6. 발행 후 일정 기간 미입금이면 운영본부가 정산 요청 메일·전화 진행 (운영본부 내부 절차)

## 4. 일정(안)

| 단계 | 내용 | 기간 |
| --- | --- | --- |
| 1 | 키 수령 · 샘플 확인 · 현장명 매핑 표 작성 | 키 수령 후 1주 |
| 2 | 읽기 연동(발행일·입금 가져오기) 시범 — 현장 2~3곳 | 1주 |
| 3 | 쓰기 연동(요청 자동 생성) 시범 | 1주 |
| 4 | 전체 적용 · 운영 규칙 확정 | 이후 |

## 5. 안전장치

- 쓰기는 **요청 생성**과 **계약 생성**뿐입니다. 기존 데이터의 수정·삭제, 발행완료·입금 상태 변경은 하지 않습니다.
- 같은 청구 건이 두 번 올라가지 않도록 우리 쪽 요청 번호를 함께 기록합니다.
- 동기화 기록(언제 무엇을 읽고 썼는지)을 남겨 문제 시 추적할 수 있습니다.
- 키는 비밀값 저장소에만 두고, 경영지원팀이 키를 삭제하면 즉시 중단됩니다.

## 6. 경영지원팀 회신 (2026-11-25) — 확정 사항

| 항목 | 결정 |
| --- | --- |
| 자동 생성 요청 | 수신 가능. 요청자 "아파트스퀘어 대시보드(담당자)" 표시 OK |
| 거래처 | **사업자등록증 상 정식 상호** 기준 (세금계산서 발행 기준과 동일, 거래처별 집계) |
| 사업자등록증 | 같은 거래처 2번째 현장부터 생략. 첫 요청에 첨부 |
| 계약서 PDF | **시범 단계 제외.** 요청 데이터(거래처·금액·청구구분)만 자동 생성. 정식 전환 시 협의 |
| 청구 구분 | 계약금 / 중도금 / 잔금 / 계약금+잔금 그대로 |
| 잔디 알림 | 시범 중 없음(목록만). 정식 전환 시 재협의 |
| 샘플 | 발행요청·계약 각 2~3건 화면 캡처(금액 가림) 전달 예정 |
| 시범 운영 | 현장 2~3곳, 1~2주, 제목 `[시범]` |
| 미수 집계 | 발행 거래처는 사업자등록 기준 통일, 입금은 경영지원팀이 세금계산서에 매칭(현행) |
| 서비스 계정 키 | `aptsquare-sync` (Cloud Datastore 사용자) 생성 완료. **USB 전달.** 운영본부 비밀값 저장소에만 보관, 개인 PC·공유드라이브·메신저 저장 금지. 삭제 권한은 경영지원팀 |
| 다음 단계 | ① 키·샘플 전달 → ② [시범] 현장 2~3곳 → ③ 1~2주 확인 후 정식 전환(계약서 자동첨부·잔디 협의) |

### 회신에 따른 우리 쪽 구현 범위 (시범)

- 거래처 마스터(정식 상호·대표자·사업자번호·주소·업태·종목·이메일·사업자등록증 파일) — 현장이 아니라 **거래처 단위**로 보관해 같은 거래처 재사용
- 계약 건에 거래처 연결 + 시범 대상 표시(연동 켜기/끄기)
- 청구 요청 버튼에 구분 선택(계약금 / 중도금 / 잔금 / 계약금+잔금) + 묶음 발행 연결
- 그쪽 계약·요청 번호 저장 칸, 현장명 매핑 표, 동기화 로그
- 동기화 함수(Supabase 서버 함수, 10분 주기): 읽기(발행완료·반려·보류·입금 매칭 → 우리 청구 항목) / 쓰기(계약 생성, 요청 생성 — 제목 `[시범]`, 첫 요청만 사업자등록증 첨부, 계약서 첨부 없음, 잔디 없음)
- 키 보관: Supabase Edge Function Secrets. USB에서 바로 열어 대시보드 비밀값 칸에 붙여 넣고 PC에 복사하지 않음

## 7. 구현 상태 (2026-11-25)

- 콘솔(거래처 명부 · 계약 건 거래처/연동 · 청구 요청 구분 · 연동 패널)과 동기화 함수(`supabase/functions/biz-sync`) 구현 완료. 키 등록 전에는 함수가 아무것도 쓰지 않고 로그만 남김.
- 시범 현장: **영통SK뷰아파트 · 태전e편한세상아파트** — 콘솔에서 계약 건 수정 → 거래처 선택 → "경영지원팀 세금계산서 시스템과 연동" 체크
- 남은 것: ① 경영지원팀 키(USB) 수령 → Edge Function Secret 등록 ② 샘플 캡처로 필드 확인(필요 시 매핑 보정) ③ `BIZ_DRY_RUN=1` 로 1회 점검 → 해제 ④ pg_cron 10분 주기 등록 ⑤ 1~2주 시범 후 정식 전환(`BIZ_PILOT_PREFIX` 비우기 · 계약서 첨부 · 잔디 알림 협의)
