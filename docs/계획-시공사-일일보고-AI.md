# 계획 — 시공사 일일보고 + AI 안전·공정 위험 탐지

작성 2026-11-12 · 상태: **계획 확정 전 (구현 시작 안 함)** · AI는 우선 API로 시작
결정: 시공사는 **B안 = 로그인 계정(`contractor` 역할)** 으로 사용

---

## 0. 목적

- 비상주 감리(주 1회 방문) → 방문 안 하는 날의 공백을 **시공사 일일보고 + AI 1차 검토**로 메움
- 그 기록(보고 원문 · AI 표시 · 감리원 처리 이력)을 **관리감독 근거**로 남김
- AI는 판정하지 않음. "검토 필요 / 이상 징후 없음 / 판단 불가"만 표시, 적합·부적합은 감리원 몫

## 2. DB 설계 — `backend/migration-daily-reports.sql`

```
profiles.role         check 에 'contractor' 추가
apartment_contractors 시공사 ↔ 현장 (다대다, apartment_auditors 와 같은 모양)
  apartment_id, contractor_id

daily_reports         일일보고 1건 (하루·공종·부위)
  apartment_id, author_id, work_date, worktype, location, memo,
  required_missing jsonb      -- 빠진 필수 촬영 항목
  rule_flags jsonb            -- 규칙 검사 결과(무료, 아래 4-①)
  ai_status  pending/done/failed/skipped
  ai_summary 검토 필요/이상 징후 없음/판단 불가
  ai_cost_tokens int          -- 비용 추적
  created_at

daily_photos          사진 1장
  report_id, path, shot_slot, sha256(중복 사진 탐지),
  exif_taken_at, exif_lat, exif_lng, exif_device, stale_flag

ai_findings           처리 단위(항목 1개)
  report_id, apartment_id, source(ai/rule), category(안전/공정·품질),
  title, reason, photo_ids[],
  state open → acknowledged → requested → replied → rechecked | false_alarm
  shared bool, escalated_at

finding_events        단계 이력(수정·삭제 불가 = 감사 기록)
  finding_id, action, actor_id, actor_name, note, photo_paths, created_at

ai_usage_daily        (날짜, 현장) 별 분석 장수·토큰 — 하루/월 상한 집행용
```

RLS
- 시공사: 자기 현장(`apartment_contractors`) 보고서 작성·조회, `ai_findings` 는 **shared=true 만**, 회신(replied) 이벤트만 쓰기
- 감리원: 담당 현장 전체 · 관리자: 전체
- `finding_events`: insert 만 (update/delete 정책 없음)
- 입주민·관리소장: 이번 단계에선 안 보임(공유 항목 노출은 다음 단계)

## 3. 화면 흐름

### ① 시공사 (앱 로그인)
- 가입 시 "시공사(현장소장)" 선택 → 관리자 승인 + 현장 배정 (기존 승인 흐름 재사용)
- 홈: 내 현장 카드 → **[오늘 일일보고]** · **[요청받은 항목 N]**
- 일일보고(30초): 날짜(자동) → 공종(STAGE_SETS) → 동·부위 → 필수 촬영 칸 → 메모 → 제출
  - 폰에서 EXIF 먼저 읽고, 1600px 로 줄여 업로드
  - 빈 필수 칸 = "사진 누락" 표시(제출은 허용, 누락 자체가 기록)
- 요청받은 항목: 감리원이 통보한 것만 보임 → **조치 사진 + 한 줄 회신**
- AI 원문 결과는 시공사에게 안 보임

### ② 감리원 (앱)
- 푸시 "검토 필요" → 항목 카드: 근거 사진 · 이유
- 버튼: [확인함] → [시공사에 통보/요청함](시공사 푸시) → (회신 도착 푸시) → [재확인 완료] / [오경보로 닫기]
- 단지 메뉴에 "📋 일일보고": 지난 방문(`done_at`) 이후 날짜별 사진·메모·AI 표시·처리 상태
- 감리일지 작성 시 "시공자 제출 작업보고 원문 수령·보관함 (기간, N건, 사진 M장)" 자동 첨부

### ③ 관리자 대시보드(콘솔) — **여기서도 전부 확인 가능**
- 새 탭 "일일보고"
  - 오늘 현장별 제출 현황(제출/미제출/누락)
  - "검토 필요" 전체 목록 + 상태 필터(미확인 · 통보함 · 회신대기 · 종결)
  - **지연 목록**: 기준 시간 넘게 미확인 → 빨간 표시(재알림 발송 이력 포함)
  - 정확도: 항목별 오경보율, 종결까지 평균 시간
  - **AI 비용**: 오늘/이번 달 분석 장수 · 토큰 · 예상 금액, 상한 대비 %
- 현장 상세에도 같은 요약 카드
- 시공사 계정 관리: 승인 · 현장 배정

### ④ 재알림
- GitHub Actions cron(매시) → 함수 호출 → 24시간(설정값) 넘게 open 인 항목 → 관리자 푸시 + `escalated_at`

## 4. AI 비용 줄이는 설계 (핵심)

### ① AI 안 쓰고 코드로 하는 검사 (무료)
AI 에게 묻기 전에 규칙으로 처리 → AI 는 "사진을 봐야만 알 수 있는 것"만
- 필수 사진 누락 → 공종별 필수 칸 비교
- 옛 사진 재사용 → EXIF 촬영일 ≠ 보고일, 같은 사진(sha256) 재업로드
- 공정 순서 건너뜀 → STAGE_SETS 순서와 직전 보고 비교 (예: 바탕처리 보고 없이 도장)
- (2단계) 강수 후 도장 → 날씨 API 값 비교
- 결과는 `ai_findings(source='rule')` 로 같은 처리 흐름에 태움

### ② 사진은 작게, 적게
- AI 에 보내는 사진은 **긴 변 1024px** (≈ 1,000 토큰/장, 1600px 원본은 저장용)
- 보고 1건당 AI 분석 **최대 6장**(필수 칸 우선) · 현장당 **하루 20장** · **월 예산 상한**(넘으면 `skipped` → "감리원 직접 확인")
- 같은 사진(해시) 재분석 안 함

### ③ 모델 · 호출 방식
- **1차 = Claude Haiku 5.5** 로 전 사진 훑기 (가장 저렴)
- "검토 필요"가 나온 건만 **Claude Sonnet 5.5 로 2차 확인** → 오경보 줄이고 비싼 모델 호출은 소수만
- 시스템 프롬프트(규칙·금지어)는 고정 → **프롬프트 캐싱**(반복분 약 90% 할인)
- 출력은 짧은 JSON 형식 고정, effort 낮게
- 모델은 시크릿(`DAILY_AI_MODEL`, `DAILY_AI_MODEL_2ND`)으로 교체 가능

### ④ 선택: 저녁 일괄 처리(Batch API, 50% 할인)
- 하루치를 저녁에 한 번에 분석 → 추가 50% 절감
- 대신 알림이 즉시가 아니라 **저녁**에 감 → 안전 항목은 즉시가 낫다고 보고, **기본은 즉시**, 비용 문제 생기면 전환

### 예상 비용 (추정치 — 실제는 첫 주 사용량으로 다시 계산)
가정: 보고 1건 = 사진 6장(1024px) + 텍스트 → 입력 약 9천 토큰, 출력 약 1.5천 토큰. 환율 1,400원/$.

| 방식 | 보고 1건 | 월 440건 (20현장×22일) |
|---|---|---|
| Opus 5.5 만 | 약 90원 | 약 4만 원 |
| Sonnet 5.5 만 | 약 45원 | 약 2만 원 |
| **Haiku 5.5 1차 + 의심건만 Sonnet 2차 (추천)** | 약 5~10원 | **약 3천~5천 원** |

(가격: Haiku 5.5 $0.10/$0.50, Sonnet 5.5 $2/$10, Opus 5.5 $4/$20 — 100만 토큰당 입력/출력, 2026-11 기준)
- Anthropic 콘솔에서 **월 지출 한도**도 같이 걸어 둘 것

## 5. AI 표현 규칙
- 결과는 `검토 필요 / 이상 징후 없음 / 판단 불가` 만
- 항목마다 근거 사진 번호 + 이유
- 금지어: 위반 · 적발 · 하자 · 부적합 · 불량 · 재시공 → 서버에서 한 번 더 검사 후 "~로 보임, 감리원 확인 필요" 로 치환
- 사진이 불명확하면 추측하지 말고 "판단 불가"

## 6. 구현 순서 (1단계)
1. 마이그레이션 SQL (역할 · 테이블 · RLS · 버킷)
2. 가입/승인에 시공사 역할 + 콘솔 현장 배정
3. 시공사 앱 화면(홈 · 일일보고 · 요청받은 항목)
4. 규칙 검사 + `daily-ai` 함수(Haiku 1차/Sonnet 2차, 상한·캐싱·금지어 필터)
5. 감리원 처리 화면 + 푸시(worker `buildPlan` 에 이벤트 추가)
6. 콘솔 "일일보고" 탭(현황 · 지연 · 정확도 · 비용)
7. 재알림 cron 워크플로우
8. 감리일지 근거 자동 첨부
9. 배포 체크리스트(SQL 실행 · 함수 배포 · 웹훅 · 워커 갱신 · 웹 배포)

2단계: 날씨 자동 연동, 관리소장 공유 화면, Batch 전환 검토

## 7. 자체 AI 전환 로드맵 (결정: 지금은 API로 시작)

- **지금**: Claude API(Haiku 1차 + Sonnet 2차). AI 호출은 `daily-ai` 함수 한 곳에만 둬서 나중에 교체 쉽게
- **운영하며 데이터 축적**: 사진 + 감리원 처리 결과(확인·재확인·오경보)가 곧 정답 데이터 → 학습용 내보내기 기능 준비
- **사진 수천 장 쌓이면**: 안전모·안전대·안전난간 탐지만 우리 모델(상업 무료 라이선스 탐지 모델)로 학습 → 시공사 폰에서 실행(서버비 0, 촬영 순간 경고)
- **상황 판단**(공정 순서·강수 후 도장 등)은 계속 Claude 또는 그때 자체 서버 오픈소스 AI 검토
- 주의: 모델·공개 데이터셋 모두 상업 사용 라이선스 확인
