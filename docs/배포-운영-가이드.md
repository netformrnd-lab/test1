# 배포 · 운영 가이드 (라이브 앱 수정하기)

앱을 **운영하면서 계속 고치는** 흐름을 정리한 문서입니다. (아파트스퀘어 · 운영팀 공용)

## 한 줄 원칙
> **`main` = 지금 라이브에 올라간 것.** 수정은 항상 최신 `main` 위에서 → 테스트 → `main` 병합 → 배포.

---

## 1. 배포는 어디로?

| 대상 | 주소 | 올리는 법 | 자동배포 |
|---|---|---|---|
| **프로덕션 (실사용)** | Cloudflare **floral-cherry-6860** | `npm run deploy` (또는 대시보드 드래그) | ❌ 수동 |
| 테스트 미리보기 | GitHub Pages | 작업 브랜치 push 시 자동 | ✅ (작업 브랜치 한정) |

- **`main`에 병합해도 프로덕션은 자동으로 안 바뀝니다.** 반드시 `npm run deploy` 를 돌려야 라이브 반영. → 그래서 `main` 병합은 안전(겁낼 필요 없음).

## 2. 평소 수정 사이클

```
1) 최신 main 에서 시작   (클라우드 세션은 자동 — 아래 4번)
2) 수정 → 테스트
3) main 에 병합
4) npm run deploy        (프로덕션 반영)
5) 유저는 앱 새로고침 → 새 버전 (캐시버스팅 ?v= 로 자동)
```

최초 1회만: `npm install` → `npx wrangler login`(브라우저에서 Cloudflare 승인).

## 3. 문제 생기면 — 롤백 (1분)

- Cloudflare 대시보드 → **Workers & Pages → floral-cherry-6860 → Deployments** → 이전 배포본 **Rollback** 클릭.
- 배포본이 버전별로 남아있어 즉시 되돌아갑니다. → 배포 자체는 안전.

## 4. 너 ↔ 운영팀 동시 작업 (충돌 방지)

- 둘 다 `main` 을 공유합니다. **수정 전 반드시 `main` 최신화.**
- **클라우드 세션(Claude Code web)은 자동**: `.claude/hooks/session-start.sh` 가 세션 시작 때 `origin/main` 을 작업 브랜치에 자동 병합합니다. (충돌이면 안전하게 멈추고 알림)
- 로컬에서 직접 작업할 때: `git fetch origin main && git merge origin/main` 먼저.
- 되도록 서로 다른 파일/영역을 만지면 충돌이 거의 안 납니다. (대부분 `변경기록.md` 정도만 겹침 → 양쪽 내용 다 살려 정리)

## 5. DB(Supabase) 변경 규칙 — ⚠️ 중요

라이브 중엔 **옛 버전 앱을 쓰는 유저(아직 새로고침 안 함)**가 있습니다. 그들이 안 깨지게:

- ✅ **추가만**: 컬럼 추가(`add column if not exists`), 테이블 추가는 안전.
- ❌ **지양**: 기존 컬럼 **삭제·이름변경·타입변경**, NOT NULL 급추가. (옛 앱이 그 컬럼을 읽다 깨짐)
- 꼭 바꿔야 하면: 새 컬럼 추가 → 앱 배포 → 유저 대부분 갱신된 뒤 → 옛 컬럼 정리, 순서로.
- 마이그레이션 SQL 은 `backend/migration-*.sql` 로 남기고, Supabase SQL Editor 에서 실행.

## 6. 큰 기능은 "숨긴 채" 배포

- 감리일지엔 이미 **입주민 공개(published)** 플래그가 있음 → 준비 안 된 건 꺼둔 채 올리고, 되면 공개.
- 서버 기능(AI 보강 등)은 **Edge Function 배포 + 키 설정 전까지 버튼만 보이고 안내만** 뜨도록 되어 있어 라이브에 올라가도 안전.

## 부록 — 서버/키가 필요한 기능 (설정해야 작동)

| 기능 | 필요한 설정 |
|---|---|
| 시공사 자동기재 | `backend/migration-apt-builder.sql` 실행 (apartments.builder 컬럼) |
| AI 보강 / 공사감리일지 PDF 자동화 | Edge Function `gamri-ai` 배포 + `ANTHROPIC_API_KEY` secret (`supabase/functions/gamri-ai/README.md`) |
| POUR 즉시연동 | Firebase 함수 배포(`deploy-fn`) + pg_net 트리거 SQL (기존) |
