# 운영팀 인수 안내 (아파트스퀘어)

서비스 운영팀이 이 저장소를 받아 **수정·배포**할 때 알아야 할 핵심만 모았습니다.

---

## 1. 이게 뭔가요 (구성)

| 폴더 | 내용 |
|---|---|
| `app/index.html`, `app/js/` | 입주민 앱 + 감리원 앱 (한 파일, 역할로 화면 분기) |
| `app/console/` | 관리자 대시보드 (공사관리·캘린더·관제·회원 등) |
| `app/inspect/` | 현장 점검 앱 = **감리 체크리스트/감리일지 작성** |
| `app/photos/` | 감리일지 사진 모아보기 페이지 |
| `backend/*.sql` | Supabase DB 변경(마이그레이션) |
| `cloudflare-push-worker/` | 앱 푸시(FCM) 발송 워커 |
| `docs/변경기록.md` | 그동안의 수정 내역 전부 |

**데이터/인프라:** Supabase(DB·인증·스토리지) · Cloudflare(웹 배포·푸시 워커) · Firebase(FCM) · 앱 호스팅은 아임웹(squarecm).

---

## 2. 어떻게 수정하나요

- **Claude Code로 "○○ 이렇게 바꿔줘"** 라고 말하면 알아서 고치고 커밋·push 합니다. 파일을 직접 안 찾아도 돼요.
- 여러 명이 같이 할 때는 **각자 브랜치 → PR → `main` 병합** (같은 파일 같은 줄을 동시에 고칠 때만 충돌, 그때만 정리).

---

## 3. 배포 (수정 → 실제 반영)

| 하는 일 | 방법 |
|---|---|
| 웹/앱 화면 | **`npm run deploy`** 한 줄 (빌드 + Cloudflare 업로드). 최초 1회만 `npm install` 과 `npx wrangler login`(브라우저 승인) |
| 웹/앱 화면 (수동) | `node build-deploy.js` → 생긴 `dist-deploy/` 를 Cloudflare 대시보드 → Workers & Pages → **floral-cherry-6860** → New deployment 에 드래그 업로드 |
| DB 변경 | `backend/*.sql` 을 **Supabase → SQL Editor** 에서 실행 |
| 푸시 수정 | `cloudflare-push-worker/worker.js` 를 Cloudflare 워커에 교체 |

## 4. ⚠️ 꼭 지킬 주의사항

### (A) 감리 체크리스트(`app/inspect/`)는 "통째 교체" 금지 → "내용만 수정"
디자이너가 준 새 HTML로 **통째로 덮으면** Supabase 연동·대시보드 전송·담당 감리원 자동채움·잔디·회차가 **같이 사라져** 전부 깨집니다.
- ✅ 권장: **Claude Code로 내용만 수정** ("○○ 항목 추가/수정")
- ✅ 새 HTML을 받았으면: 통째로 덮지 말고 **"내용만 합쳐줘"** 로 처리
- 🛟 자동 안전장치: `build-deploy.js` 가 핵심 연동 누락 시 **빌드를 중단**합니다 (깨진 버전 배포 차단). 자세한 건 **`docs/체크리스트-교체-주의.md`**

### (B) 비밀값은 코드/깃에 넣지 않기
Supabase service_role 키, Firebase 서비스계정 키, 푸시 secret 등은 **코드가 아니라** Supabase/Cloudflare의 **환경변수·시크릿**에만 둡니다. (저장소엔 공개용 anon 키만)

### (C) DB 트리거/연동 함부로 삭제 금지
`notify_push()`(푸시), POUR 동기화, 잔디 알림 등은 **DB 트리거/워커**로 돌아갑니다. 함수·트리거를 지우면 해당 알림이 멈춰요.
