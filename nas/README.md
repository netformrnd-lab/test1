# 브랜드 대시보드 — NAS 연결 설치 안내서

코드를 몰라도 따라 할 수 있게 썼습니다. **위에서부터 순서대로** 하시면 됩니다.

---

## 이게 무슨 작업인가요?

지금 대시보드는 데이터를 **내 브라우저 안에만** 저장합니다.
그래서 다른 PC에서 열면 빈 화면이고, 브라우저 기록을 지우면 데이터가 날아갑니다.

NAS에 올리면 **회사 안 어느 PC에서 접속해도 같은 데이터**를 보게 됩니다.

```
[지금]   내 PC 브라우저 ── 데이터가 여기 갇혀 있음

[NAS 연결 후]
   김대리 PC ┐
   박과장 PC ┼─→  NAS의 data/brand-data.json  (하나뿐인 원본)
   회의실 PC ┘
```

---

## 0단계. 우리 NAS 확인 — ✅ 완료

RaiDrive 화면으로 확인이 끝났습니다. 이 단계는 건너뛰셔도 됩니다.

| 항목 | 확인된 값 | 어떻게 알았나 |
|---|---|---|
| 제조사 | **시놀로지 (Synology)** | 주소가 `synology.me` (시놀로지 전용 DDNS) |
| 외부 주소 | `netformrnd.synology.me` | RaiDrive 주소 칸 |
| 사용 중인 기능 | **WebDAV** (포트 5006 = WebDAV HTTPS) | RaiDrive 포트 칸 |
| 보안 | TLS 1.3 적용됨 | RaiDrive TLS/SSL 칸 |
| 현재 연결 | RaiDrive로 `Z:`, `Y:` 드라이브 연결 중 | RaiDrive 좌측 목록 |
| **내부 IP** | **`192.168.0.37`** | DSM 제어판 → 네트워크 |
| Web Station | **이미 설치됨** (포트 80/443 동작 중) | 패키지 센터 → 설치됨 |

즉 **아래 시놀로지 기준 안내를 그대로 따라가시면 됩니다.**

### DSM 관리자 화면 접속 주소
```
https://netformrnd.synology.me:5001
```
(5001은 DSM 관리자 페이지 기본 포트입니다. 사내에서는 `https://[NAS내부IP]:5001` 도 됩니다)

> **참고 — WebDAV로는 안 되나요?**
> 이미 WebDAV(5006)가 켜져 있지만, 대시보드는 브라우저에서 실행되기 때문에
> WebDAV에 직접 저장할 수 없습니다(브라우저 보안 정책이 막습니다).
> 그래서 아래처럼 **Web Station**을 추가로 켜는 방식이 필요합니다.
> 기존 WebDAV 설정은 그대로 두시면 되고, 서로 영향을 주지 않습니다.

## 1단계. 웹 서버 기능 켜기 — ✅ 설치 완료, PHP만 확인

**Web Station은 이미 설치되어 동작 중입니다** (기본 포털 / 포트 80·443 / 상태 "보통").
따라서 설치는 건너뛰고, **PHP가 켜져 있는지만** 확인하면 됩니다.

### 1-1. PHP 패키지 설치
Web Station → 왼쪽 **스크립트 언어 설정** → PHP 탭을 보면
"사용 가능한 PHP 패키지가 없습니다"라고 나옵니다. (초기 상태로, 정상입니다)

**패키지 센터**를 열고 `php`로 검색해 **가장 높은 버전 하나**를 설치합니다.
(예: `PHP 8.2`. `PHP 7.4` 같은 낮은 버전은 설치할 필요 없습니다)

### 1-2. PHP 프로필 만들기 ⚠️ 빠뜨리기 쉬운 단계
패키지를 설치했다고 바로 쓸 수 있는 게 아니라, **프로필을 만들어야** 합니다.

Web Station → **스크립트 언어 설정** → PHP 탭 → **`생성`** 버튼
- 프로필 이름: 아무거나 (예: `brand`)
- 나머지는 **기본값 그대로 두고 저장**

### 1-3. 기본 서버에 PHP 연결
Web Station → 왼쪽 **웹 서비스** → `기본 서버` 선택 → **편집**
- **백엔드 서버**: Apache 또는 Nginx (무엇이든 상관없습니다)
- **PHP**: 1-2에서 만든 프로필 선택 → **저장**

> 이 3단계를 마치면 NAS 설정은 끝입니다. 이후는 파일 복사뿐입니다.

> `web` 공유 폴더는 Web Station 설치 시 이미 만들어져 있습니다.

## 2단계. 파일 올리기 (5분)

**File Station**을 열고 `web` 폴더 안에 `brand`라는 폴더를 새로 만든 뒤,
아래 3개 파일을 그 안에 올립니다.

| 올릴 파일 | 어디 있나요 |
|---|---|
| `brand.html` | 이 저장소 맨 위 |
| `load.php` | 이 저장소의 `nas` 폴더 |
| `save.php` | 이 저장소의 `nas` 폴더 |
| `files.php` | 이 저장소의 `nas` 폴더 (자료 파일 업로드·다운로드) |
| `deploy.sh` | 이 저장소의 `nas` 폴더 (자동 업데이트) |

**주의:** `nas` 폴더째로 올리지 말고, **파일 3개가 같은 폴더에 나란히** 있어야 합니다.

> ## ⚠️ 반드시 File Station으로 만들고 올리세요
>
> 윈도우 탐색기(RaiDrive `Z:` 드라이브)로 **폴더를 만들면 저장 기능이 고장납니다.**
> 탐색기로 만든 폴더에는 PHP 실행 계정(`http`)의 **쓰기 권한이 들어가지 않기** 때문입니다.
>
> 증상이 헷갈립니다 — **화면은 잘 열리는데 저장만 실패**합니다.
> 웹서버는 파일을 읽기만 하면 되니 읽기 권한만으로 화면은 멀쩡히 뜨거든요.
>
> 파일을 **덮어쓰는 것**은 탐색기로 해도 괜찮습니다. 문제가 되는 건 **폴더 생성**입니다.

```
web/
└── brand/
    ├── brand.html
    ├── load.php
    ├── save.php
    ├── files.php
    ├── deploy.sh
    └── data/                  ← 처음 저장할 때 자동으로 생깁니다
        ├── brand-data.json    ← 입력한 글자 (브랜드·자동화·히스토리·메모·프롬프트)
        ├── backup-2026-09-01.json
        └── files/                    ← 자료 탭에 올린 실제 파일
            ├── POUR공법/
            │   ├── 제품 카탈로그 2026.pdf
            │   └── 단가표.xlsx
            └── 아파트스퀘어/
                └── 브랜드 가이드.pdf
```

> 파일은 **브랜드 이름 폴더에 원래 이름 그대로** 저장됩니다.
> 탐색기(`Z:\web\brand\data\files\`)에서 열어도 바로 알아볼 수 있고,
> 이 폴더 자체가 정리된 자료 보관함이 됩니다.
>
> ⚠️ **탐색기에서 파일 이름을 바꾸거나 옮기지 마세요.** 대시보드의 다운로드 링크가 끊어집니다.
> 정리는 대시보드에서 하시고, 탐색기는 보는 용도로만 쓰세요.

## 3단계. 대시보드 설정 — ✅ 할 일 없음

예전에는 `brand.html`을 열어 `STORAGE_MODE`를 직접 고쳐야 했지만,
**이제는 자동으로 판단합니다.** 파일을 열어볼 필요가 없습니다.

| 어떻게 열었나 | 저장 위치 | 화면 배지 |
|---|---|---|
| `http://192.168.0.37/brand/brand.html` | **NAS** (모두 공유) | 🟢 NAS 공유 저장 |
| 파일을 더블클릭 (`file:///C:/...`) | 이 브라우저에만 | 🟡 이 브라우저에만 저장 |

즉 **NAS 주소로 열면 자동으로 NAS에 저장**됩니다.

## 4단계. 접속해서 확인하기

사내망 PC에서 브라우저를 열고 아래 주소로 들어갑니다.

```
사내망 (이 주소를 직원들에게 공유하세요):

    http://192.168.0.37/brand/brand.html
```

즐겨찾기에 등록해두면 편합니다.

> Web Station의 기본 포트는 **80(HTTP) / 443(HTTPS)** 입니다.
> DSM 관리자 포트(5001)나 WebDAV 포트(5006)와는 다른 포트이니 헷갈리지 마세요.

화면 오른쪽 위 배지가 **🟢 NAS 공유 저장**으로 바뀌면 성공입니다.

이제 숫자를 입력하고 **[저장]**을 누른 뒤, **다른 PC에서 같은 주소로 접속**해 보세요.
같은 숫자가 보이면 연결이 제대로 된 것입니다.

## 대시보드를 수정할 때 (앞으로 계속 쓰게 될 절차)

기능을 추가하거나 화면을 바꾸면, 아래 3단계로 반영합니다. **30초면 됩니다.**

1. 저장소에서 **`brand.html` 하나만** 새로 받습니다
2. NAS의 `web/brand/` 폴더에 **덮어쓰기**
3. 브라우저에서 **`Ctrl` + `F5`** (강력 새로고침)

### 데이터는 절대 안 날아갑니다

`brand.html`과 데이터 파일은 **완전히 별개**이기 때문입니다.

```
web/brand/
├── brand.html             ← 화면 틀.   수정 시 이것만 교체
├── load.php  save.php     ← 거의 안 바뀜
└── data/
    └── brand-data.json    ← 입력한 숫자. 교체와 무관, 그대로 유지
```

`brand.html`을 100번 교체해도 `data/` 폴더는 건드리지 않으므로 데이터는 그대로입니다.

> **불안하면**: 교체 전에 대시보드에서 **[📤 내보내기]** 한 번 눌러두세요.
> 문제가 생겨도 **[📥 가져오기]** 로 되돌릴 수 있습니다.

## (선택) 구글시트 문의 기록 연결하기

구글시트의 문의 기록을 브랜드별 「📞 문의」 탭에 표시하는 기능입니다.
**시트를 외부에 공개하지 않아도 됩니다.** n8n이 시트를 읽어 NAS로 보내는 방식입니다.

### 왜 이 방식인가

시트를 「웹에 게시」하면 주소를 아는 사람은 누구나 볼 수 있게 됩니다.
문의 기록에는 고객명과 연락처가 들어있으므로 그 방식은 쓰지 않습니다.

### 준비 — 시트 조건

브랜드를 구분하는 열이 있어야 합니다. 열 이름은 `브랜드` / `brand` / `브랜드명` 중 하나면 됩니다.
값은 대시보드의 브랜드 이름과 같아야 합니다. (띄어쓰기 차이는 무시합니다)

| 날짜 | **브랜드** | 고객명 | 연락처 | 공종 | 유입 | 내용 | 상태 |
|---|---|---|---|---|---|---|---|
| 2026-08-28 | 아파트스퀘어 | 김관리 | 010-... | 옥상방수 | 전화 | 옥상 누수 견적 | 현장방문예정 |

나머지 열은 자유입니다. **있는 열을 그대로 표로 보여줍니다.**

### 브랜드마다 시트가 다를 때

시트를 **여러 개** 연결할 수 있습니다. 브랜드마다 시트가 따로 있어도 됩니다.

```
브랜드 → 📞 문의 → [🔗 시트 관리]

🔗 연결된 구글시트                브랜드마다 다른 시트를 붙일 수 있습니다

  통합 시트          [시트의 브랜드 열 사용]     [브랜드] [연결 해제]
  https://docs.google.com/…/pub?output=csv

  슈어포인트 문의     [슈어포인트 전용]          [브랜드] [연결 해제]
  https://docs.google.com/…/pub?output=csv

  [＋ 시트 연결]  [↻ 지금 가져오기]
```

시트를 추가할 때 **어느 브랜드 것인지** 물어봅니다.

- **0 (시트의 브랜드 열 사용)** — 시트에 「브랜드」 열이 있는 경우.
  한 시트에 여러 브랜드가 섞여 있어도 열을 보고 나눕니다.
- **브랜드 번호** — 그 브랜드 전용 시트인 경우.
  **「브랜드」 열이 없어도 됩니다.** 열 이름이 달라도(등록일·현장·문의유형 …) 상관없습니다.

여러 시트를 합쳐서 보여주며, 한 시트를 못 가져와도 나머지는 그대로 나옵니다
(실패한 시트는 이유와 함께 표시됩니다).

### 방법 1 — 시트 주소 연결 (한 번만 설정, 이후 자동)

1. 구글시트 → **파일 → 공유 → 웹에 게시** → 형식 **쉼표로 구분된 값(.csv)** → 게시
2. 나온 주소를 복사
3. 대시보드 → **📞 문의** 탭 → **[🔗 시트 연결]** → 주소 붙여넣기

이후로는 **새로고침 없이 알아서 최신이 됩니다.**

| 언제 | 무엇이 |
|---|---|
| **30초마다** | 화면이 "바뀐 게 있나" 만 확인 (38 바이트) |
| **1분마다** | NAS 가 구글시트에 물어봄 |
| 문의 탭을 열 때 | 그 자리에서 한 번 더 확인 |

새 문의가 들어오면 대시보드에 **약 1분 안에** 나타납니다.
지금 당장 보려면 **[↻ 시트에서 가져오기]** 를 누르세요.

> ⏱️ **구글 쪽 시차가 있습니다.**
> 「웹에 게시」한 주소는 구글이 자기 서버에 몇 분 정도 담아둡니다.
> 시트에 방금 적은 내용이 그 주소에 반영되기까지 **보통 몇 분** 걸립니다.
> 이건 구글이 정하는 것이라 대시보드에서 줄일 수 없습니다.
> 그래서 실제로는 **「구글 시차 + 1분」** 뒤에 보인다고 생각하시면 됩니다.
>
> 급할 때는 시트에서 **파일 → 공유 → 웹에 게시 → 게시** 를 다시 누르면
> 구글이 바로 갱신해 줍니다.

여러 명이 대시보드를 열어두어도 NAS 는 **1분에 한 번만** 구글에 갑니다.
(같은 시각에 8명이 열어도 실제 요청은 한 번인 것을 확인했습니다)

> ⚠️ 「웹에 게시」한 주소는 **주소를 아는 사람이면 누구나 볼 수 있습니다.**
> 고객 이름·연락처가 들어있다면 그 점을 감안하고 쓰셔야 합니다.
> 게시를 중단하려면 같은 화면에서 「게시 중지」를 누르면 됩니다.

### 방법 2 — CSV 올리기 (설정 없이 바로)

1. 구글시트에서 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**
2. 대시보드 → 아무 브랜드 → **📞 문의** 탭 → **[📥 시트 CSV 올리기]**

올릴 때마다 **전체가 교체**되므로, 항상 최신 시트를 받아 올리시면 됩니다.
시트를 외부에 공개하지 않아도 되고, n8n도 필요 없습니다.

### 방법 3 — n8n으로 자동화 (기존 워크플로는 건드리지 않습니다)

**새 워크플로를 하나 만드세요.** 기존 자동화와 완전히 별개로 돌아갑니다.

```
[Schedule Trigger]  매일 1회
        ↓
[Google Sheets]  Get Rows
        ↓
[Code]  아래 코드
        ↓
[HTTP Request]  POST
```

**Code 노드**
```javascript
return [{ json: {
  source: 'n8n-google-sheets',
  token: '',                                  // config.php 에 토큰을 넣었다면 같은 값
  rows: $input.all().map(i => i.json)
}}];
```

**HTTP Request 노드**
| 항목 | 값 |
|---|---|
| Method | `POST` |
| URL | `http://192.168.0.37/brand/inquiries.php?action=push` |
| Body Content Type | `JSON` |
| Body | `{{ $json }}` |

### 확인
```
http://192.168.0.37/brand/inquiries.php?action=check
```
`"보관건수"` 와 `"브랜드별"` 이 나오면 성공입니다.

- 내용이 전부 빈 행은 버립니다

## (선택) NAS 공유폴더 파일 찾기

수만 개 파일이 흩어져 있어도 **대시보드에서 이름으로 찾을 수 있게** 하는 기능입니다.
**파일을 옮기거나 복사하지 않습니다.** 어디에 있는지 목록만 만듭니다.

### 1. 대시보드에서 바로 만들기 (권장 — 작업 스케줄러 필요 없음)

```
대시보드 → 🗂️ NAS 자료 → [🔎 지금 파일 목록 만들기]
```

훑을 폴더를 물어본 뒤 바로 시작하고, **진행 상황을 화면에 보여줍니다.**

```
⏳ 목록 만드는 중                                      42초  [중단]
   찾은 파일        18,420개
   훑은 폴더           612개
   /volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/…
```

- 몇 초씩 나눠 훑기 때문에 파일이 수만 개라도 **시간 초과로 끊기지 않습니다**
- 다 되면 폴더가 바로 뜨고, 브랜드에도 자동으로 붙습니다
- **다 될 때까지 창을 닫지 마세요** (닫으면 중간에 멈춥니다. 다시 누르면 처음부터 다시 합니다)
- 읽기만 하며 파일을 옮기거나 고치지 않습니다

**PHP가 공유폴더를 못 읽게 막혀 있으면 (가장 흔한 원인):**

```
PHP 가 공유폴더를 읽지 못하도록 막혀 있습니다.

DSM → 웹 스테이션 → 스크립트 언어 설정 → 쓰고 계신 PHP 프로필 → 편집 →
"open_basedir" 칸에 아래 경로를 추가하고 저장해 주세요.

    /volume1/넷폼알앤디 공유폴더
```

시놀로지 웹 스테이션은 기본적으로 PHP가 **웹 폴더 밖을 못 보게** 묶어둡니다
(`open_basedir`). 공유폴더를 읽으려면 그 경로를 허용 목록에 넣어야 합니다.
여러 경로는 콜론(`:`)으로 이어 씁니다.

```
/volume1/web:/volume1/넷폼알앤디 공유폴더
```

저장한 뒤 웹 스테이션이 다시 시작될 때까지 10~20초 기다렸다가 다시 눌러보세요.

**공유폴더 읽기 권한 주기 (가장 흔한 막힘)**

웹 서버는 **`http`** 라는 계정으로 돌아갑니다. 이 계정에 읽기 권한이 없으면
아무리 사장님 계정에 권한을 줘도 대시보드는 폴더를 못 읽습니다.

⚠️ 시놀로지는 권한 화면이 **두 곳**인데, `http` 계정은 아래 화면에서만 보입니다.

```
DSM → 제어판 → 공유 폴더 → 그 폴더 선택 → [편집] → [권한] 탭
  1. 화면 위 드롭다운을 "로컬 사용자" → "시스템 내부 사용자" 로 바꿉니다
  2. 목록에서 http 를 찾아 "읽기 전용" 에 체크합니다
  3. 저장
```

File Station → 속성 → 권한 에서 주는 것만으로는 안 되는 경우가 많습니다.
공유 폴더 자체의 권한을 위 화면에서 주셔야 합니다.

지금 웹 서버가 어떤 계정으로 도는지는 아래에서 확인할 수 있습니다.

```
http://192.168.0.37/brand/nasfiles.php?action=check
```
→ `"웹서버계정": "http"`

**폴더 접근 권한이 없으면 이렇게 알려줍니다:**

```
이 폴더를 읽을 권한이 없습니다: /volume1/넷폼알앤디 공유폴더

File Station 에서 이 공유폴더를 오른쪽 클릭 → 속성 → 권한 에서
"http" 사용자에게 읽기 권한을 주고, "하위 폴더에 적용" 을 체크해 주세요.
```

### 2. (선택) 매일 밤 자동으로 갱신하기

한 번 만들어두면 그 상태로 계속 쓸 수 있지만, 새로 올라오는 파일까지
자동으로 따라가려면 작업 스케줄러에 등록해 두시면 됩니다.

```
DSM → 제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트
```

| 항목 | 값 |
|---|---|
| 작업 이름 | `NAS 파일 목록 만들기` |
| 사용자 | `root` |
| 일정 | 매일 새벽 (예: 03:00) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/scan.sh` |

`scan.sh` 는 대시보드에서 정한 폴더(`data/scanroot.txt`)를 그대로 씁니다.

### 3. 확인

```

```

`"파일수"` 에 숫자가 찍히면 성공입니다.

## 🗂️ 업무 (회의록 · 달력 · 마케팅 비용)

회의록·달력·마케팅 비용은 **브랜드 안이 아니라 브랜드 목록 아래 「업무」 묶음**에
있습니다. 한 번의 회의에서 여러 브랜드 이야기가 같이 나오고, 마감 일정도 브랜드를
넘나들며, 돈은 브랜드끼리 견줘 봐야 하기 때문입니다.

```
왼쪽 목록
 ├ 🏠 홈
 ├ 📁 NAS 자료
 ├ 브랜드
 │   ├ 아파트스퀘어      ← 문의·자동화·할 일·자료 …
 │   └ POUR공법
 └ 업무
     ├ 🗣️ 회의록          ← 브랜드 공통
     └ 📅 달력            ← 브랜드 공통
```

예전에 브랜드 안에 적어둔 회의록은 **처음 열 때 자동으로 「업무 → 회의록」으로
옮겨지고**, 어느 브랜드에서 적었는지는 딱지로 남습니다. 손으로 옮길 것은 없습니다.

### 📅 달력

마감·발행·촬영·미팅 같은 팀 일정을 적어둡니다.

**[＋ 일정 넣기]** 를 누르면 창이 열립니다.

| 칸 | |
|---|---|
| 일정 이름 * | 예: 9월 블로그 4편 마감 |
| **날짜** * | **달력에서 골라 넣습니다** |
| 끝나는 날 (선택) | 며칠에 걸치는 일정이면 마지막 날 |
| 종류 | 마감 · 발행 · 촬영 · 미팅 · 기타 |
| 브랜드 (선택) | 등록된 브랜드에서 고릅니다 |
| 메모 (선택) | 같이 알아야 할 것 |

- **빈 칸을 두 번 누르면** 그 날짜가 미리 채워진 채로 창이 열립니다
- **일정을 누르면 고치는 창**이 열립니다. **날짜도 여기서 바꿉니다.** 지우기도 이 창에서 합니다
- 끝나는 날을 넣으면 그 사이 날짜에 **한 덩어리로 이어져** 보입니다
  (`● 부산 현장 촬영` → `… 부산 현장 촬영` → `… 부산 현장 촬영`)
- 끝나는 날이 시작하는 날보다 앞이면 저장되지 않고 알려줍니다
- 브랜드 **할 일의 기한**도 초록 점으로 같이 보입니다 (누르면 그 할 일로 갑니다)

**하이웍스 휴가·전자결재는 아직 연결하지 않았습니다.** 읽어오기만 하면 하이웍스
쪽은 아무것도 바뀌지 않아 안전한데, 캘린더를 읽는 방법(캘린더 API 또는 ICS 주소)을
아직 확인하지 못했습니다.

같은 회의록·일정을 **둘이 같은 시간에 고치면**, 나중에 저장한 사람 것이 남고
상대가 쓴 것은 `— 같은 시간에 다른 사람이 고친 것` 이라는 이름으로 **바로 아래에
따로 남습니다.** 둘 다 읽어보고 필요 없는 쪽을 지우면 됩니다. 글이 사라지지 않습니다.

### 🗣️ 회의록 (AI 정리)

회의에서 들은 대로 편하게 적어두면, **AI가 읽고 정리해 줍니다.**
회의를 적을 때 **브랜드**를 골라두면 「브랜드로 보기」로 걸러볼 수 있고,
`[→ 할 일로]` 도 그 브랜드의 할 일로 들어갑니다.

| AI가 나눠주는 것 | |
|---|---|
| **요약** | 무엇을 논의했고 무엇이 정해졌는지 3~6문장 |
| **결정된 것** | 정해진 것만 |
| **할 일** | 담당·기한까지. `[→ 할 일로]` 를 누르면 할 일 탭으로 넘어갑니다 |
| **다음에 다룰 것** | 다음 회의 주제 |
| **사람이 확인해야 할 것** | 메모만으로는 불분명해 AI가 짚어둔 것 |

정리한 뒤에는 원문이 접히고 요약이 위에 옵니다. 원문은 그대로 남아 있어
`▸ 회의 내용 원문` 을 누르면 언제든 볼 수 있습니다.

### 처음 한 번만 — AI 키 넣기 (챗GPT · 클로드 둘 다 됩니다)

이미 쓰고 계신 쪽 키를 그대로 넣으시면 됩니다. **넣은 키를 보고 어느 회사 AI 인지
알아서 갈라 씁니다.**

| 쓰는 것 | 키 만드는 곳 | 키 모양 |
|---|---|---|
| **챗GPT** | platform.openai.com → API keys | `sk-…` |
| **클로드** | console.anthropic.com | `sk-ant-…` |

1. 위에서 키를 하나 만듭니다
2. 업무 → 회의록 → **[🔑 AI 키 넣기]** → 붙여넣기

챗GPT 키를 넣으면 **모델은 계정이 실제로 쓸 수 있는 것 중에서 대시보드가 골라
`data/ai-model.txt` 에 적어둡니다** (gpt-5 → gpt-4.1 → gpt-4o 순으로 살펴봅니다).
모델 이름이 바뀌어도 알아서 다시 고르므로 손댈 것이 없습니다.

> **주의: 챗GPT 구독료(Plus)와 API 는 다른 지갑입니다.** 구독 중이어도
> platform.openai.com 쪽에 결제 수단·크레딧이 있어야 API 가 동작합니다.
> 클로드도 마찬가지입니다.

**키는 NAS 에만 저장됩니다.** 브라우저에 두면 대시보드를 여는 누구나 볼 수 있어서,
`data/ai-key.php` 에 PHP 파일로 둡니다 — 주소로 직접 열어도 내용이 보이지 않고
빈 화면이 나옵니다. 화면에는 앞 7글자만 표시하고, 전체는 어떤 응답에도 담지 않습니다.

AI 를 부르는 것도 NAS 입니다. 사무실 브라우저는 밖으로 못 나가기 때문입니다.

### 돈이 듭니다 — 잔액이 떨어지면 전부 멈춥니다

회의 한 건 정리에 **몇 십 원 수준**입니다 (회의록 길이에 따라 다릅니다).
쓴 횟수는 `ai.php?action=check` 에서 볼 수 있습니다.
키를 안 넣으면 회의록은 그냥 **적어두는 용도**로 쓸 수 있고, AI 단추만 동작하지 않습니다.

**API 는 양쪽 다 선불(크레딧) 입니다.** 잔액이 0 이 되면 회의 요약도,
마스터프롬프트 만들기도 **그 순간부터 전부 멈춥니다.** 이렇게 뜹니다:

> 💳 AI 잔액이 떨어졌습니다. … credit balance is too low … / … exceeded your current quota …

**챗GPT 는 잔액이 없을 때도 「429」 로 알려옵니다.** 그래서 겉보기에는
「요청이 몰렸습니다」 처럼 보일 수 있는데, 대시보드가 안에 든 문구를 보고
돈 문제인지 진짜 몰린 것인지 갈라서 알려줍니다. 진짜로 몰린 것이면
**6초 쉬었다가 한 번 더 물어보고**, 그래도 안 되면 알려줍니다.

**충전하는 곳**

| 쓰는 것 | 어디서 |
|---|---|
| 챗GPT | platform.openai.com → **Billing** → 결제 수단·크레딧 추가 |
| 클로드 | console.anthropic.com → **Plans & Billing** → Buy credits |

충전하면 **바로** 다시 됩니다 (대시보드에서 다시 켜거나 키를 새로 넣을 필요 없습니다).

- 이 크레딧은 **챗GPT Plus·클로드 Pro 같은 구독료와 별개**입니다. 구독 중이어도
  API 크레딧이 없으면 대시보드의 AI 는 동작하지 않습니다.
- **자동 충전(Auto-reload)** 을 켜두면 갑자기 멈추는 일을 막을 수 있습니다.
- 잔액이 없는 동안에도 **[📋 브랜드북 복사]** 로 밖에서 만들어 붙여넣으면 됩니다.

### AI 를 믿을 때 주의할 점

- 회의록에 **없는 내용은 지어내지 말라고** 지시해 두었고, 불분명한 것은
  「사람이 확인해야 할 것」에 넣게 했습니다. 그래도 **읽어보고 쓰세요.**
- 담당자·기한은 메모에 적혀 있을 때만 채웁니다. 추측하지 않습니다.
- 회의록이 아주 길면(6만 자 넘으면) 앞부분만 보고 정리하며, 그렇다고 알려줍니다.

|---|---|
| **닿나** | AI 서버(api.anthropic.com) · 다른 사이트(github) 각각 닿는지 |
| **나가는 방법** | curl 확장 · allow_url_fopen · openssl · shell_exec · wget · **지금 쓸 수 있는 길** |
| **주소찾기(DNS)** | 이름을 IP 로 바꿀 수 있는지 |
| **키 확인** | 넣어둔 AI 키가 지금도 받아들여지는지 (글자를 만들지 않아 돈이 들지 않습니다) |
| **이렇게 해보세요** | 위 결과를 보고 지금 할 일을 한두 줄로 |

> **401 은 「막혔다」 가 아니라 「닿았다」 입니다.** 키 없이 물어보면 AI 서버가
> 401 을 돌려주는데, 그 답이 왔다는 것 자체가 길이 열려 있다는 뜻입니다.

**PHP 로는 https 로 못 나가는 NAS 가 많습니다.** `curl 확장`과 `openssl` 이
둘 다 꺼져 있으면 PHP 는 https 주소에 아예 접근하지 못하고, 남는 길은
`wget` 하나뿐입니다. 대시보드는 그 wget 으로도 정상 동작하지만, 켜두는 편이
빠르고 안정적입니다 — DSM → 웹 스테이션 → **PHP 프로필** → 우리 프로필
[편집] → **확장** 에서 `curl` 과 `openssl` 을 켜고 저장하세요.
(그 다음이 DNS, 그 다음이 방화벽입니다)

**당장 급하면 AI 없이도 됩니다.** 브랜드북 위의 **[📋 브랜드북 복사]** 를 누르고
클로드·챗GPT 대화창에 붙여넣은 뒤, 받은 글을 아래 프롬프트 칸에 넣으면 결과는
같습니다.

## ✅ 할 일은 맡은 사람 것 (계정을 쓸 때)

로그인을 켜두면 할 일마다 **맡은 사람**을 정합니다.

| 누가 보나 | |
|---|---|
| **팀원** | 자기 할 일 + **공용**으로 둔 것만 보입니다 |
| **관리자** | 모두 보입니다. 위쪽 **[👥 누구 것]** 으로 사람별로 걸러 봅니다 |

- 할 일을 새로 넣으면 **넣은 사람 것**이 기본입니다.
  관리자는 창에서 **다른 사람**이나 **공용 (모두 봅니다)** 로 바꿀 수 있습니다.
- 팀원 화면에는 남의 할 일이 **아예 오지 않습니다.** 화면에서 감추는 것이 아니라
  서버(`load.php`)가 보내지 않습니다. 저장할 때는 서버가 안 보이던 할 일을
  그대로 지켜주기 때문에, 팀원이 저장해도 남의 할 일이 지워지지 않습니다.
- 계정을 쓰지 않으면 예전처럼 **담당자 이름을 글자로** 적고, 모두가 다 봅니다.

### 자료 파일도 주소로 열리지 않습니다

예전에는 `data/brand-data.json` 주소를 알면 **로그인 없이도** 브라우저로 내용이
그대로 보였습니다. 지금은 `data/brand-data.php` 로 두고 첫 줄에 `exit` 를 넣어,
주소로 열면 **빈 화면**이 나옵니다 (하루치 백업 파일도 같이 가렸습니다).
프로그램은 첫 줄만 건너뛰고 읽으므로 하는 일은 그대로입니다.
**예전 `.json` 파일은 처음 열 때 자동으로 옮겨집니다** — 따로 하실 일은 없습니다.

> 아직 열려 있는 것: 구글시트에서 받아온 **문의 자료**(`data/inquiries.json`)는
> 아직 주소로 열립니다. 같은 방식으로 가릴 수 있으니 필요하면 말씀해 주세요.

## ✏️ 문의 내용 고치기

문의 화면에서 **[📋 전체 목록 펼치기]** 를 누르면 표가 나옵니다.
**칸을 누르면 그 자리에서 바로 고칠 수 있습니다.**

### 두 종류의 칸이 있습니다

| | 처리상태 · 담당자 · 메모 | 접수날짜 · 고객명 · 문의내용 … |
|---|---|---|
| 어디서 온 것 | 우리끼리 쓰는 칸 (구글시트에 없음) | 구글시트에서 온 값 |
| 고치면 | 그냥 저장됩니다 | ✎ 표시가 붙습니다 |
| 비우면 | 빈 칸이 됩니다 | **시트 원래 값으로 되돌아갑니다** |

`[칸 고르기]` 로 우리끼리 쓰는 칸을 바꿀 수 있습니다 (최대 8개).
처리상태와 메모는 **최근 문의 목록에도** 함께 보입니다.

### 시트를 다시 가져와도 안 지워집니다

이게 핵심입니다. 대시보드는 1분마다 구글시트를 다시 가져오는데,
고친 값을 시트에 쓰는 게 아니라 **NAS 에 따로 보관**(`data/inquiry-edits.json`)
했다가 가져올 때마다 그 위에 얹습니다. 그래서 덮어써지지 않습니다.

**원본 구글시트는 전혀 건드리지 않습니다.** 시트에서 보면 그대로입니다.
(「웹에 게시」 주소는 읽기 전용이라 대시보드가 시트에 쓸 방법이 없습니다)

다른 분 화면에는 **30초 안에** 반영됩니다.

### 한 가지 주의할 점

각 줄은 **그 줄의 내용으로 알아봅니다.**
그래서 **시트에서 그 줄의 내용을 고치면**(고객명 오타 수정 등)
대시보드에서 그 줄에 적어둔 메모와의 연결이 끊깁니다.

시트에 **「문의번호」·「접수번호」·「ID」** 같은 열이 있으면 그걸로 알아보기 때문에
이런 일이 생기지 않습니다. 오래 쓰실 거면 시트에 번호 열을 하나 두시는 편이 좋습니다.

## 📈 문의 추이 (브랜드 홈)

브랜드를 고르면 나오는 **📞 문의** 화면 위쪽에 그래프와 표가 함께 나옵니다.

- **가로축은 달(1~12월), 선 하나가 한 해**입니다.
  작년 9월과 올해 9월을 나란히 볼 수 있어 계절 흐름이 보입니다.
- 점에 마우스를 올리면 그 달의 모든 해 숫자가 함께 나옵니다.
- 그래프 아래 **표**에 같은 숫자가 그대로 있습니다.
  (숫자로 확인하거나 복사해 쓰실 때)

### 읽을 때 주의할 점

- **아직 오지 않은 달은 그리지 않습니다.** 올해는 이번 달까지만 선이 이어지고,
  표에는 `–` 로 둡니다. 0건과 구분하기 위해서입니다.
  이번 달도 진행 중이라 마지막 점은 아직 늘어날 수 있습니다.
- 선 끝의 `2026 →` 는 "아직 진행 중" 이라는 뜻입니다.
- **기록이 없던 달도 그리지 않습니다.** 9월부터 기록이 시작된 해는 1~8월을
  0건으로 긋지 않고 9월부터 선이 시작합니다. 표에는 `–` 로 둡니다.
- 색은 **그 해에 고정**되어 있어서, 해가 바뀌어도 2025년은 늘 같은 색입니다.
  (4살 차이로 색이 겹치는 경우에만 한쪽이 남는 색으로 비켜갑니다)
- 한 번에 **최근 4개 해**까지 그립니다. 그보다 오래된 것도 표에는 전부 있습니다.
- 날짜를 읽지 못한 문의가 있으면 몇 건인지 그래프 아래에 적어둡니다.
  (시트의 날짜 칸이 비어 있거나 형식이 다른 경우)

### ✎ 숫자를 손으로 고치기

**표의 숫자를 누르면 그 자리에서 고칠 수 있습니다.**

| 쓸 데 | |
|---|---|
| 구글시트에 없는 **옛날 자료** | 2022년처럼 시트가 시작되기 전 숫자를 채워 넣습니다 |
| **틀린 숫자** | 시트에 잘못 들어간 달을 화면에서만 바로잡습니다 |

- **구글시트는 바뀌지 않습니다.** 화면에 보일 때만 덮어씁니다.
  시트에서 그 달의 문의가 늘어나도, 고쳐둔 숫자가 계속 이깁니다.
- 고친 칸은 **연한 노란 바탕에 ✎** 로 표시되고, 마우스를 올리면
  **시트 원래 숫자**가 나옵니다.
- **칸을 비우면** 고친 것이 지워지고 시트 숫자로 돌아갑니다.
  한꺼번에 되돌리려면 위쪽 **[↩︎ 고친 숫자 되돌리기 (N)]** 를 누릅니다.
- 0 이상의 정수만 들어갑니다.
- 고친 숫자는 **그래프·합계·분기별에 모두 반영**됩니다.
  (분기는 월을 더한 값이라 월별에서만 고칠 수 있습니다)
- **분류로 좁혔거나 찾는 중일 때는 시트 숫자만** 보여줍니다.
  고친 숫자는 브랜드 전체 기준이라 섞이면 헷갈리기 때문입니다.
- 팀 전체가 함께 봅니다. 두 사람이 **서로 다른 달**을 같은 시간에 고쳐도
  둘 다 남습니다 (달 칸 하나하나가 따로 합쳐집니다).

## 🔐 로그인 (퇴사자 차단)

**계정을 하나도 안 만들면 예전처럼 누구나 씁니다.** 계정을 만든 순간부터
로그인해야 들어올 수 있습니다.

### 처음 한 번

1. 위쪽 **[👤 계정]** 을 누릅니다
2. **관리자 한 명**을 만듭니다 (아이디 · 이름 · 비밀번호)
3. 그 뒤 **[👤이름] → 3. 사람 관리** 에서 팀원을 넣습니다

### 퇴사자 막기

**[👤이름] → 사람 관리 → [🚫 사용 중지]**

- 그 사람이 **지금 열어둔 화면까지 그 자리에서 끊깁니다.** 새로고침을 기다릴 필요 없습니다
- 다시 로그인하려 해도 「사용이 중지되었습니다」 라고 막힙니다
- **지우기보다 중지를 권합니다.** 계정이 남아 있어야 누가 무엇을 고쳤는지 기록이 이어집니다
- 관리자가 한 명도 안 남는 경우는 막아둡니다

### 어디까지 막히나

로그인 없이는 **모든 통로가 막힙니다** — 자료 불러오기·저장, 파일 올리기·내려받기,
문의 시트, NAS 파일 찾기, 문서 내용 찾기, 채널, AI, 접속자 표시까지 전부입니다.
주소를 직접 쳐도 `{"ok":false,"로그인필요":true}` 만 나옵니다.

### 비밀번호

- 8글자 이상, 숫자만은 안 됩니다. `0000`·`password`·회사 이름이 들어간 것도 막습니다
- **원문은 어디에도 저장하지 않습니다** (`password_hash`)
- 8번 틀리면 10분간 잠깁니다
- 비밀번호를 바꾸면 **다른 컴퓨터에서 열어둔 것이 모두 로그아웃**됩니다
- 잊어버렸으면 관리자가 **[비번 초기화]** 로 새로 정해줍니다
- 로그인은 14일 뒤 만료됩니다

### ⚠️ 꼭 알아두실 것

지금 대시보드는 **사무실 안(http)** 에서만 씁니다. **https 가 아니라서
비밀번호가 사내망을 그대로 지나갑니다.** 사무실 안에서만 쓰는 동안에는
퇴사자·외부인을 막는 목적으로 충분하지만, **바깥에서 접속하게 하려면
반드시 Web Station 에서 https 를 먼저 켜세요.**

계정 정보는 `data/users.php` 에 있습니다. 주소로 직접 열어도 빈 화면만
나옵니다. 이 파일을 지우면 다시 「계정 없음」 상태(누구나 사용)로 돌아갑니다.

## 📂 올린 파일을 공유폴더에 저장하기

기본은 대시보드 안(`data/files`)입니다. **공유폴더로 바꾸면** 탐색기에서
바로 열어볼 수 있는 자리에 쌓입니다.

브랜드 → **📁 자료** 맨 위에, 아직 대시보드 안에 쌓이고 있으면 **노란 안내**가 뜹니다.

| 단추 | |
|---|---|
| **[📂 마케팅 공유폴더로 바꾸기]** | 한 번에 그 폴더로 (아래 주소를 알아서 찾습니다) |
| **[📁 폴더 골라서 정하기]** | NAS 안을 눈으로 뒤져 고릅니다. **가장 확실합니다** |
| **[주소 직접 넣기]** | 윈도우 주소를 붙여넣습니다 |

```
Y:\넷폼알앤디 공유폴더\마케팅 공유폴더 외장하드 백업\브랜드 마케팅팀
```

드라이브 문자(`Y:`)는 컴퓨터마다 다르므로, NAS 안에서 같은 이름의 폴더를
찾아 알아서 연결합니다. 띄어쓰기나 괄호가 조금 달라도 찾아냅니다.
그래도 못 찾으면 **[📁 폴더 골라서 정하기]** 로 직접 눌러 들어가세요.

### 예전에 올린 파일도 옮기기

이미 `data/files` 에 쌓여 있던 파일은 **함께 옮길지 물어봅니다.**
나중에 **[📦 예전에 올린 N개도 옮기기]** 로 언제든 옮길 수 있고,
옮긴 뒤에도 대시보드에서 그대로 내려받을 수 있습니다.

```
브랜드 마케팅팀/
  _폴더 안내.txt
  아파트스퀘어/
```

### 📅 연도 폴더 끄고 켜기

해마다 파일이 몇 개 안 되는 브랜드는 연도 폴더가 오히려 번거로울 수
있습니다. 안내 상자의 **[📅 연도 폴더 쓰는 중]** 을 누르면 끕니다
(다시 누르면 켭니다). 누르는 즉시 이미 쌓여 있던 파일도 그 모양에
맞게 옮겨 담고, 대시보드가 아는 자리도 같이 고칩니다.

| | 파일이 놓이는 자리 |
|---|---|
| 연도 폴더 **쓰는 중** (처음 값) | `아파트스퀘어/01_자료/2026/2026-09-04_….pdf` |
| 연도 폴더 **안 씀** | `아파트스퀘어/01_자료/2026-09-04_….pdf` |

연도는 **파일 이름 앞의 날짜**로 정합니다. 날짜가 없던 파일은 정리할 때
만들어진 날짜가 앞에 붙으므로, 옛날 파일도 제 해의 폴더로 들어갑니다.

### 🧹 폴더 정리하기

이미 흩어져 있는 파일이 있으면 **[🧹 폴더 정리하기]** 한 번이면 됩니다.
정리할 곳이 있으면 단추가 진해지고 몇 곳인지 알려줍니다.

| 무엇을 하나 | |
|---|---|
| 브랜드 폴더에 **그냥 널려 있던 파일** | 이름을 보고 01/02/03 중 맞는 곳으로 |
| 연도 폴더 설정과 **다르게 놓인 파일** | 지금 설정대로 (연도 폴더 안 ↔ 밖) |
| 예전 폴더 이름 (`자료`·`기록부`) | 지금 이름으로 합침 |
| 날짜가 없는 파일 이름 | 만들어진 날짜를 앞에 붙임 |
| 빈 폴더 | 치움 |

옮기면서 **대시보드가 아는 자리도 같이 고칩니다.** 혹시 놓친 것이 있어도
파일 이름으로 다시 찾기 때문에 내려받기가 끊기지 않습니다.

### 🗑️ 지울 때 — 어느 쪽이 어느 쪽을 따라가나

| 어디서 지우나 | 무슨 일이 일어나나 |
|---|---|
| **대시보드**에서 [삭제] | 공유폴더의 **파일도 함께 지워집니다** (바로) |
| **탐색기**에서 파일 삭제 | 목록은 남습니다. 자료 탭을 열면 **「🚫 파일 없음」** 으로 표시되고, **[🧹 목록에서도 지우기]** 한 번으로 정리됩니다 |

탐색기 쪽은 대시보드가 알 방법이 없어서(윈도우가 알려주지 않습니다)
**자료 탭을 열 때마다 실제로 있는지 확인**하는 방식으로 맞췄습니다.

- 파일을 **폴더만 옮긴** 경우는 이름으로 다시 찾아 계속 열립니다
- **공유폴더에 닿지 못하는 동안**(네트워크 끊김, 권한 문제)에는 아무것도
  「없어졌다」고 하지 않습니다. 잠깐 끊긴 것을 지워진 것으로 오해하면
  목록이 통째로 지워질 수 있기 때문입니다
- 파일을 다시 제자리에 넣어두고 **[🔄 다시 확인]** 을 누르면 되살아납니다
- [🧹 목록에서도 지우기] 는 **Ctrl+Z** 로 되돌릴 수 있습니다

### 주의

- 그 폴더에 **http 사용자 쓰기 권한**이 있어야 합니다.
  없으면 바꿀 때 그 자리에서 알려줍니다 (실제로 써 보고 확인합니다).
- 폴더를 다시 바꿔도 **예전에 올린 파일은 계속 열립니다.**
- 탐색기에서 이름을 바꾸면 대시보드에서 못 찾을 수 있습니다
  (지운 것은 위와 같이 「파일 없음」 으로 표시됩니다).

## 📖 문서 내용으로 찾기

파일 **이름**이 아니라 문서 **안에 적힌 글자**로 찾습니다.
NAS 자료 → **[📖 내용으로 찾기]**

### 순서

1. **[🧪 얼마나 읽히나 재보기]** — 몇 %나 읽히는지 몇 초 만에 재봅니다
2. **[📖 글자 목록 만들기]** — 문서를 읽어 글자 목록을 만듭니다 (문서가 많으면 몇 분)
3. 이제 검색창에 말을 넣으면 그 말이 **적혀 있는 문서**가 나옵니다

원본 파일은 **읽기만 하고 고치지 않습니다.**

### 읽을 수 있는 것

| 형식 | |
|---|---|
| 워드·엑셀·PPT (docx·xlsx·pptx) | PHP 의 **zip** 기능이 켜져 있어야 합니다 |
| PDF | **글자층이 있는** PDF 만. 스캔한 PDF(사진)는 안 됩니다 |
| txt·csv·md·log·json·xml·html | 그대로 읽습니다 |

### 안 될 때 — [🩺 이 NAS 점검]

이 단추를 누르면 **이 NAS 가 무엇을 할 수 있는지** 알려줍니다.
zip·mbstring·zlib 이 켜져 있는지, 형식마다 실제로 하나씩 읽어본 결과가 나옵니다.

`HTTP 500` 과 함께 알 수 없는 화면이 나오면, 작업이 오래 걸려서
**웹 서버가 먼저 끊은 것**입니다. 잠시 뒤 다시 눌러보고, 그래도 같으면
[🩺 이 NAS 점검] 결과를 확인해 주세요.

## 🔍 파일 찾기

파일 이름의 일부만 넣으면 찾습니다. 띄어쓴 말은 **모두 들어간** 파일만 나옵니다.
(`제안서 최종` → 두 낱말이 다 들어간 파일)

### 두 군데에서 찾을 수 있습니다

| 어디서 | 찾는 범위 |
|---|---|
| **브랜드 → 📁 자료 탭** 맨 위 | 그 브랜드에 **연결한 NAS 폴더 안**만 |
| **맨 위 검색창** | 대시보드에 등록된 것 **＋ NAS 전체** |

브랜드 자료 탭에서는 등록해 둔 자료 카드도 함께 찾아줍니다.
형식(PDF·엑셀·사진 …)으로 좁힐 수도 있습니다.

찾은 파일은 그 자리에서 **[⬇ 내려받기]** 하거나,
**[📋 경로]** 로 탐색기 주소를 복사할 수 있습니다. 사진은 미리보기가 붙습니다.

### 파일 이름 vs 폴더 이름

경로 전체에서 찾기 때문에 「제안서」 폴더 안의 `단가표.xlsx` 도 걸립니다.
그런 파일은 뒤로 밀고 `(폴더 이름 일치)` 라고 적어둡니다.

### 빠르게 하려면

파일 목록(`data/nasfiles.tsv`)이 있으면 **몇 만 개여도 즉시** 찾습니다.
없으면 폴더를 직접 훑는데, 6초가 넘으면 거기서 멈추고 그렇다고 알려줍니다.

브랜드 자료 탭 검색은 그 브랜드 폴더만 보므로 목록이 없어도 대체로 빠릅니다.
**맨 위 검색창은 NAS 전체를 보므로**, 파일이 많다면
작업 스케줄러에 `scan.sh` 를 걸어두시는 편이 좋습니다 (위 「NAS 파일 목록」 참고).

## ⚡ 실시간으로 같이 보기

**새로고침하지 않아도** 다른 분이 고친 내용이 몇 초 안에 화면에 나타납니다.
따로 켤 것도, 설정할 것도 없습니다.

| | 시간 |
|---|---|
| 상대가 고침 → 내 화면에 반영 | **약 2~3초** |
| 다른 창을 보고 있을 때 | 15초 (돌아오면 즉시) |

### 어떻게 되는 건가요

2초마다 **"판 번호만"** 물어봅니다 (`load.php?rev=1` — **85 바이트**).
번호가 달라졌을 때만 전체 내용을 받아옵니다.

그래서 자주 물어봐도 NAS 가 힘들지 않습니다.
시험해 보니 **한 번에 0.6밀리초**, 초당 2,000건까지 처리했습니다.
5명이 2초마다 물으면 초당 2.5건이니 여유가 아주 많습니다.

- 글을 쓰는 중에 상대 내용이 들어와도 **쓰던 글과 커서는 그대로** 입니다.
- 아직 저장 안 한 내 수정이 있으면, 저장할 때와 똑같이 **항목 단위로 합쳐서**
  받아옵니다. 내 것도 상대 것도 사라지지 않습니다.
- 누가 고쳤는지 아래에 잠깐 뜹니다 — `🔄 김마케님이 방금 고친 내용을 가져왔습니다`

### 지금 누가 보고 있는지

오른쪽 위에 `🟢 3명 김마케, 이디자인` 처럼 표시됩니다.
누르면 **내 이름**을 정할 수 있습니다. (이 브라우저에만 저장됩니다)

이름과 지금 보고 있는 화면 이름 말고는 아무것도 기록하지 않고,
5분 넘게 소식이 없으면 자동으로 지워집니다.

## 👥 여러 명이 같이 쓸 때

팀에서 동시에 열어놓고 써도 되도록 만들어져 있습니다. 아래는 실제로 시험해서
확인한 내용입니다.

### 괜찮은 경우

| 상황 | 결과 |
|---|---|
| 상대가 고친 것이 내 화면에 | 2~3초 안에 (새로고침 없이) |
| 서로 다른 브랜드를 동시에 편집 | 둘 다 남습니다 |
| 같은 브랜드의 다른 탭 (자동화 / 할 일) | 둘 다 남습니다 |
| 같은 브랜드, 같은 목록에 각자 추가 | 둘 다 남습니다 |
| 한 명이 브랜드를 추가하는 동안 다른 사람이 편집 | 둘 다 남습니다 |
| 한 명이 항목을 지우고 다른 사람이 추가 | 지운 건 지워지고, 추가한 건 남습니다 |
| 5명이 동시에 마구 등록 | 15건 전부 남았습니다 |
| 같은 이름의 파일을 6명이 동시에 업로드 | `제안서.txt`, `제안서 (2).txt` … 로 각각 저장 |
| 8명이 동시에 대시보드를 염 | 채널 확인은 한 번만 나갑니다 |
| 다른 사람이 저장하는 중에 새로 열기 | 반쪽짜리 데이터를 읽지 않습니다 |
| 긴 글을 쓰는 중에 다른 사람이 계속 저장 | 쓰던 글·커서 그대로 |
| 같은 항목을 둘이 동시에 수정 | 내 것이 남고, 상대 것은 노란 띠에 보관 |
| 같은 마스터프롬프트를 둘이 동시에 작성 | 위와 같음 — 어느 쪽도 안 사라짐 |
| 수정창을 열어둔 사이 그 항목이 지워짐 | 쓰던 내용을 새 항목으로 저장 |
| 보고 있던 브랜드를 다른 사람이 지움 | 홈으로 이동 (오류 없음) |

### 어떻게 되는 건가요

- **저장할 때마다 판 번호(`_rev`)가 올라갑니다.** 내가 불러온 뒤에 다른 사람이
  저장했으면, 그대로 덮어쓰지 않고 **항목 하나씩 대조해서 합칩니다.**
  화면에는 "다른 분이 저장한 내용과 합치는 중…" 이 잠깐 뜹니다.
- **저장은 통째로 바꿔치기(rename)** 합니다. 그래서 다른 사람이 읽는 순간에도
  '이전 것' 아니면 '새 것' 중 하나만 보입니다. 반쯤 쓰인 파일은 나가지 않습니다.
- **불러오기에 실패하면 저장하지 않습니다.** 빈 화면을 저장해서 팀 자료를
  날리는 사고를 막기 위한 안전장치입니다. 이때는 빨간 띠로 알려줍니다.

### 글을 쓰는 중에도 화면이 흔들리지 않습니다

- **쓰던 글이 날아가지 않습니다.** 화면이 다시 그려져도 입력칸의 내용·커서 위치·
  선택 상태를 그대로 되돌려 놓습니다. (긴 프롬프트를 쓰는 중에 다른 분이 계속
  저장해도 한 글자도 안 사라지는 것을 확인했습니다)
- **단추가 좌우로 밀리지 않습니다.** 「수정됨 / 저장 중 / 저장됨」처럼 글자 길이가
  바뀌는 것들은 따로 묶어, 오른쪽 단추들의 자리가 고정돼 있습니다.
- **스크롤 위치가 유지됩니다.** 표를 내려서 보고 있을 때 화면이 갱신돼도
  맨 위로 튀지 않습니다.
- 보고 있던 브랜드를 다른 분이 지우면 홈으로 돌아갑니다 (오류 없이).
- 수정창을 열어둔 사이 그 항목이 지워졌으면, 쓰시던 내용을 새 항목으로 넣습니다.

### 같은 것을 둘이 동시에 고쳤을 때

화면 위에 **노란 띠**가 뜹니다. 지금 화면에는 **내가 쓴 것**이 남고,
**다른 분이 쓴 내용은 그 띠 안에 그대로 보관**됩니다.
`[📋 복사]` 로 가져다 쓰거나, 다 확인했으면 `[확인함]` 으로 치우면 됩니다.
마스터프롬프트도 마찬가지입니다. **어느 쪽 글도 버려지지 않습니다.**

### 아직 조심해야 하는 것

- **[📥 가져오기]로 백업 파일을 되돌리면** 그 사이 다른 분이 넣은 내용도
  함께 사라집니다. 그래서 누를 때 한 번 더 물어봅니다.
- 같은 글을 **글자 단위로 합쳐주지는 않습니다.** 두 사람이 같은 문단을 고치면
  한쪽이 화면에 남고 다른 쪽은 노란 띠에 보관됩니다. 합치는 것은 사람이 합니다.

되돌려야 할 일이 생기면 `data/backup-날짜.json` 이 하루 한 번씩 쌓여 있습니다.

## 📣 채널 새 글 자동으로 받아오기

블로그·유튜브는 "새 글 올라갔어요" 하고 알려주는 구조가 아닙니다.
누군가 **가서 확인**해야 합니다. 그 일을 NAS 가 대신하게 해두는 것입니다.

등록해 두면 이렇게 됩니다.

| | 등록 전 | 등록 후 |
|---|---|---|
| 새 글 확인 시점 | 대시보드를 켜 뒀을 때만 | NAS 가 30분마다 미리 |
| 채널 탭 여는 속도 | 몇 초 기다림 | 바로 뜸 |
| 새 글 표시 | 없음 | 홈·왼쪽 목록에 빨간 숫자 |

### 등록하는 법

```
DSM → 제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트
```

| 항목 | 값 |
|---|---|
| 작업 이름 | `브랜드 채널 새 글 확인` |
| 사용자 | `root` |
| 일정 | 매일 · 반복 `30분` (원하시는 간격으로) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/feeds.sh` |

만들고 나서 목록에서 선택 → **[실행]** 을 눌러 한 번 돌려보세요.

### 확인

```
http://192.168.0.37/brand/channels.php?action=summary
```

`"자동확인"` 에 시각이 찍혀 있으면 잘 돌고 있는 것입니다.
대시보드 채널 탭에도 `NAS가 마지막으로 돌아본 때` 로 표시됩니다.

### 등록 안 해도 되나요

돌아가긴 합니다. **대시보드를 열어두는 동안에는** 30분마다 알아서 새로 받아옵니다.
다만 아무도 대시보드를 안 켜 둔 동안에는 확인하지 않습니다.

| | 예약 작업 등록 안 함 | 등록함 |
|---|---|---|
| 대시보드를 켜 뒀을 때 | 30분마다 확인 | 30분마다 확인 |
| 아무도 안 켰을 때 | 확인 안 함 | **계속 확인** |
| 아침에 처음 열었을 때 | 그때 받아오느라 몇 초 걸림 | 이미 받아둬서 바로 뜸 |

지금 어느 쪽인지는 **채널 탭 맨 위 안내 상자**가 알려줍니다.
🕒 노란 상자면 등록 안 된 것, ✅ 초록 상자면 등록된 것입니다.

`[↻ 전부 새로 받기]` 를 누르면 언제든 즉시 다시 받아옵니다.

> 여러 사람이 대시보드를 동시에 열어도 NAS 는 한 번만 나갑니다.
> (마지막으로 확인한 지 30분이 안 지났으면 그냥 넘어갑니다)

### 예약 작업을 걸었는데도 안 되는 것 같으면

`feeds.sh` 는 두 가지 방법을 차례로 시도합니다.

1. 명령줄 PHP 로 직접 실행 — 주소를 몰라도 되어 가장 확실합니다
2. 안 되면 웹 주소로 호출 (`http://localhost/브랜드폴더이름/channels.php`)

둘 다 실패하면 `/volume1/web/brand/feeds.log` 에 시도한 주소와 이유가 남습니다.
웹 주소가 다르면 `feeds.sh` 위쪽의 `URL=` 에 직접 넣어주세요.

### 새 글 표시(빨간 숫자)는 어떻게 정해지나요

**보는 사람마다 따로** 계산됩니다. 내가 마지막으로 채널 탭을 연 시점보다
뒤에 올라온 글만 새 글로 칩니다. 이 기록은 그 사람 브라우저에만 남고
NAS 에 저장되지 않아서, 다른 팀원의 표시에는 영향을 주지 않습니다.
채널 탭을 열면 그 브랜드의 새 글 표시는 사라집니다.
`"훑은폴더": "기록 없음"` 이면 아직 한 번도 성공하지 못한 것입니다.

### 새 파일은 자동으로 보이나요?

**폴더를 열어볼 때는 자동입니다.** 대시보드가 그 폴더의 디스크를 직접 읽기 때문에,
다른 직원이 방금 올린 파일도 **새로고침만 하면 바로** 보입니다. 목록을 다시 만들 필요가 없습니다.

**자동이 아닌 곳은 두 군데입니다.**

| 기능 | 새 파일 반영 |
|---|---|
| 폴더 열어보기 · 사진 보기 · 내려받기 | 🟢 바로 (새로고침) |
| 🔍 이름으로 찾기 | 🔴 목록을 다시 만들어야 함 |
| 🪄 브랜드 자동 연결 | 🔴 목록을 다시 만들어야 함 |

찾기와 자동 연결은 **미리 만들어 둔 목록**을 봅니다. 수만 개 파일을 매번 훑으면
느리기 때문입니다. 새 폴더가 생겼거나 검색에 안 잡히면
🗂️ NAS 자료 → **[🔎 목록 다시 만들기]** 를 한 번 눌러 주세요.

매일 밤 자동으로 갱신하려면 아래 "(선택) 매일 밤 자동으로 갱신하기" 를 보세요.

### 폴더 그대로 열어보기 (탐색기처럼)

대시보드 왼쪽 **🗂️ NAS 자료** 를 열면, 공유폴더가 **정리된 폴더 구조 그대로** 보입니다.
폴더를 눌러 타고 들어가고, 파일 옆 **[⬇]** 를 누르면 바로 내려받습니다.

```
🗂️ NAS 자료

[📁 폴더로 보기] [🔍 이름으로 찾기] [⚙️ 훑을 폴더 바꾸기]      12,480개 파일

[⬆ 상위 폴더] [↻ 새로고침] [📋 폴더 경로] [＋ 브랜드에 연결]   폴더 아래 전체 1,204개

🏠 00. 브랜드 공유폴더 › 공법

  📁 카탈로그          212개 · 1.4 GB      📁 시공사례        640개 · 8.1 GB
  📁 제안서            340개 · 2.2 GB

  📘 공법 개요.docx                       88 KB · 2026-08-20   [⬇]
```

- **🏠 이나 폴더 이름** 을 누르면 그 단계로 바로 되돌아갑니다
- **[🔍 이름으로 찾기]** 로 찾은 결과에서 **[📁 이 폴더 열기]** 를 누르면 그 파일이 있는 폴더가 열립니다
- 한 폴더에 파일이 500개를 넘으면 500개까지만 보여줍니다. 그 위는 이름으로 찾아주세요

### 브랜드 자동 연결 — 손으로 지정할 필요 없습니다

목록만 한 번 만들어두면, **폴더 이름과 브랜드 이름을 맞춰봐서 저절로 연결**됩니다.
브랜드마다 폴더를 지정해 주실 필요가 없습니다.

```
🗂️ NAS 자료 → 🪄 브랜드 자동 연결

  🧱 POUR공법          🪄 공법 · 1,204개
  🏢 아파트스퀘어        🪄 아파트스퀘어 · 860개
  ⚙️ POUR 솔루션        🪄 솔루션 · 412개
  🏘️ 단지온            🪄 단지온 · 96개

  어느 브랜드에도 안 붙은 폴더 — #_마케팅팀
```

- `공법` → **POUR공법**, `솔루션` → **POUR 솔루션** 처럼 앞뒤 말이 붙어 있어도 알아봅니다
- 폴더 이름 앞의 번호(`00.`)와 기호(`#_`), 띄어쓰기는 무시하고 비교합니다
- 브랜드를 새로 추가하면 **이름이 맞는 폴더가 저절로 붙습니다**
- 폴더 이름이 브랜드 이름과 많이 다르면 안 붙습니다 → 아래 "직접 연결" 을 쓰시면 됩니다
- 잘못 붙은 폴더는 그 브랜드 📁 자료 탭에서 **[숨기기]** 로 뺄 수 있습니다

### 직접 연결하고 싶을 때

찾는 것에서 끝나지 않고, **브랜드 자료 탭에 폴더를 연결해두면** 거기서 바로 열어보고 내려받을 수 있습니다.
**파일을 옮기거나 복사하지 않습니다.** 있는 자리에서 그대로 내보냅니다.

자동으로 안 붙는 폴더는 이렇게 붙이시면 됩니다.

방법 1 — 🗂️ NAS 자료에서 그 폴더까지 들어간 뒤 **[＋ 브랜드에 연결]**
방법 2 — 브랜드 → 📁 자료 탭 → **[📂 NAS 폴더 직접 연결]** 에 경로 붙여넣기

```
📁 자료 탭

📂 공법 공유폴더                    [🔍 폴더 안에서 찾기] [연결 해제]
   /volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/00. 브랜드 공유폴더/공법

   [↻ 새로고침] [📋 폴더 경로]                     폴더 아래 전체 1,204개
   🏠 공법 › 카탈로그

     📕 POUR공법 카탈로그.pdf        1.2 MB · 2026-08-28   [⬇]
     📕 방수 소개서.pdf              880 KB · 2026-08-20   [⬇]
```

- 연결한 폴더 **안쪽까지 타고 들어갈 수 있고**, 연결한 폴더보다 위로는 올라가지 않습니다
- 파일이 많으면 **[🔍 폴더 안에서 찾기]** 로 하위 폴더까지 한 번에 훑어 좁힐 수 있습니다 (조건은 저장됩니다)
- **연결 해제해도 NAS의 실제 파일은 그대로** 남습니다. 목록에서만 사라집니다
- 탐색기 형식(`\\netformrnd\...`)으로 붙여넣어도 알아서 변환합니다

### 훑을 폴더 바꾸기

목록을 만들 **최상위 폴더**를 바꾸려면 대시보드에서 하면 됩니다.

```
🗂️ NAS 자료 → [⚙️ 훑을 폴더 바꾸기] → 경로 입력
```

**탐색기 주소창에서 복사한 그대로 붙여넣으시면 됩니다.** 아래 세 형태를 모두 알아듣습니다.

```
Y:\넷폼알앤디 공유폴더\마케팅 공유폴더 외장하드 백업\00. 브랜드 공유폴더
\\netformrnd\넷폼알앤디 공유폴더\마케팅 공유폴더 외장하드 백업\00. 브랜드 공유폴더
/volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/00. 브랜드 공유폴더
```

폴더 이름의 **띄어쓰기 · 점(`.`) · `#`** 은 그대로 두셔도 됩니다
(`00. 브랜드 공유폴더`, `#_마케팅팀` 모두 그대로 넣으시면 됩니다).
경로를 못 찾으면 **어떤 경로들을 찾아봤는지** 창에 그대로 보여드립니다.

> 시놀로지가 만드는 `#recycle`(휴지통)과 `@eaDir`(썸네일)만 목록에서 빠집니다.
> `#` 으로 시작하는 사장님 폴더는 빠지지 않습니다.

바꾼 값은 `data/scanroot.txt` 에 저장되며, **자동 업데이트로 덮어써지지 않습니다.**
바꾼 뒤에는 **작업 스케줄러에서 `scan.sh` 를 한 번 더 실행**해야 새 목록이 만들어집니다.

> 폴더를 좁힐수록 목록 만드는 시간이 짧아지고 화면도 깔끔해집니다.
> 브랜드 자료만 쓸 거라면 `00. 브랜드 공유폴더` 로 좁히는 쪽을 권합니다.

### 안전장치

- **읽기만 합니다.** 파일을 옮기거나 고치거나 지우지 않습니다
- 목록을 새로 만들다 실패하면 **기존 목록을 그대로 둡니다**
- 시놀로지가 만드는 `@eaDir`, `#recycle`, `.DS_Store` 는 목록에서 제외
- 검색 결과에서 **경로 복사** → 탐색기 주소창에 붙여넣으면 바로 열립니다
  (`\\netformrnd\넷폼알앤디 공유폴더\...` 형태로 변환해 줍니다)

## 파일이 빠졌거나 꼬였을 때 — 복구 주소

`save.php` 하나만 살아 있으면, 나머지 파일을 스스로 받아옵니다.

```
http://192.168.0.37/brand/save.php?action=bootstrap
```

브라우저로 이 주소를 열면 `brand.html`, `load.php`, `files.php`, `deploy.sh` 를
GitHub에서 직접 받아 제자리에 놓습니다. 결과가 이렇게 나오면 성공입니다.

```json
{ "ok": true, "결과": { "brand.html": "설치 완료", "deploy.sh": "설치 완료" } }
```

이미 최신이면 `"이미 최신"` 으로 표시되고 아무것도 바꾸지 않습니다.
**파일을 손으로 옮길 일이 없도록** 만들어 둔 장치이니, 뭔가 꼬이면 이 주소부터 열어보세요.

## ⚠️ 파일 업로드 용량 한도 올리기 (자료 탭을 쓰려면 필수)

PHP는 기본값이 **업로드 2MB / 요청 8MB** 로 매우 작습니다.
이 상태로는 카탈로그 PDF 하나도 못 올립니다. **한 번만 올려두면 됩니다.**

### 지금 한도 확인
```
http://192.168.0.37/brand/files.php?action=check
```
`"php업로드한도": "2M"` 처럼 나오면 아래대로 바꾸세요.

### 바꾸는 법
1. **Web Station → 스크립트 언어 설정 → PHP 탭**
2. `Default Profile` 선택 → **편집**
3. **「코어」 탭** 으로 이동
4. 아래 두 값을 찾아 수정

| 항목 | 권장값 |
|---|---|
| `upload_max_filesize` | `200M` |
| `post_max_size` | `210M` |

> `post_max_size`는 `upload_max_filesize`보다 **조금 더 크게** 잡아야 합니다.
> 파일 외에 다른 정보도 같이 전송되기 때문입니다.

5. **저장** → 위 확인 주소를 다시 열어 `200M` 으로 바뀌었는지 확인

`memory_limit`이 `256M` 이상인지도 함께 봐두면 좋습니다.

## (선택) 자동 업데이트 — 파일 복사를 아예 없애기

수정할 때마다 파일을 옮기는 게 번거로우면, **NAS가 스스로 최신 파일을 받아오게** 할 수 있습니다.
한 번만 설정하면 그 뒤로는 손댈 일이 없습니다.

```
Claude가 수정 → GitHub에 올림 → NAS가 정해진 시간에 자동으로 받아옴 → 새로고침만
```

### 설정 방법 (10분, 한 번만)

**1.** `deploy.sh` 파일을 NAS의 `web/brand/` 폴더에 올립니다 (다른 파일과 같은 위치)

**2.** DSM → **제어판** → **작업 스케줄러** → **생성** → **예약된 작업** → **사용자 정의 스크립트**

**3.** 아래처럼 설정합니다

| 항목 | 값 |
|---|---|
| 작업 이름 | `브랜드 대시보드 업데이트` |
| 사용자 | `root` |
| 일정 | 매일 / 원하는 시간 (또는 몇 시간마다) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/deploy.sh` |

**4.** 만든 작업을 선택하고 **실행** 버튼으로 한 번 돌려봅니다.
`web/brand/deploy.log` 파일에 `갱신: brand.html` 같은 기록이 남으면 성공입니다.

### 스크립트 스스로 최신화됩니다

`deploy.sh` 자체가 바뀌어도 다음 실행 때 자동으로 새 버전으로 교체됩니다.
**처음 한 번만** NAS에 올려두면, 이후로는 손댈 일이 없습니다.

### 이 스크립트의 안전장치

파일을 자동으로 덮어쓰는 일이라, 아래를 확인한 뒤에만 교체합니다.

- 내려받은 파일이 **비어 있거나 깨져 있으면 교체하지 않고** 기존 파일을 그대로 둡니다
- **내용이 바뀐 파일만** 교체합니다 (매번 덮어쓰지 않음)
- `data/` 폴더(입력한 숫자)는 **절대 건드리지 않습니다**
- 네트워크 오류로 실패해도 기존 화면은 멀쩡히 동작합니다

### 주의

자동이라는 건 **검토 없이 반영된다는 뜻**이기도 합니다.
급하게 확인이 필요한 변경이라면 자동 실행을 기다리지 말고,
작업 스케줄러에서 **[실행]** 버튼을 눌러 즉시 반영하세요.

## 인터넷 없는 사내망에서 차트 보이게 하기

회사 네트워크가 외부 인터넷을 막아둔 경우, 그래프 자리에
"차트 라이브러리를 불러오지 못했습니다"라고 뜹니다. **숫자와 표는 정상 동작**하며,
그래프만 안 보이는 상태입니다. 아래처럼 고칩니다.

1. 인터넷이 되는 PC에서 이 주소를 엽니다:
   `https://cdn.jsdelivr.net/npm/chart.js@4/dist/chart.umd.min.js`
2. `Ctrl+S`로 파일을 저장합니다.
3. 파일 이름을 정확히 **`chart.umd.min.js`** 로 바꿉니다.
4. NAS의 `web/brand/` 안에 **`vendor`** 폴더를 만들고 그 안에 넣습니다.

```
web/brand/
├── brand.html
├── load.php
├── save.php
└── vendor/
    └── chart.umd.min.js
```

새로고침하면 그래프가 나옵니다. (이후로는 인터넷 없이도 계속 동작합니다)

- `save.php`가 **하루에 한 번 자동 백업**을 만듭니다 (`data/backup-2026-08-31.php`)

  **스냅샷(Snapshot Replication)** 또는 **Hyper Backup**을 켜두시길 권합니다.
- 중요한 시점에는 대시보드의 **[📤 내보내기]** 버튼으로 내 PC에도 한 부 받아두세요.

## 자주 겪는 문제

### 화면에 시놀로지 오류 페이지(HTML)가 나올 때

웹 스테이션은 **200 이 아닌 응답의 내용을 자기 오류 페이지로 바꿔치기** 합니다.
그래서 "권한 없음(403)", "폴더 없음(404)" 같은 진짜 이유가 화면에 닿지 못하고
`<!DOCTYPE html>` 로 시작하는 시놀로지 페이지만 보였습니다.

지금은 **모든 응답을 200 으로 보내고, 실패 여부는 JSON 안의 `ok` 로만** 알립니다.
원래 상태 코드는 `status` 값으로 함께 담깁니다.

> 새 PHP 파일을 만드실 일이 있으면 `http_response_code()` 로 오류 코드를 보내지 마세요.
> 내용이 통째로 버려집니다.


**Q. 접속하면 화면 대신 코드 글자가 잔뜩 나옵니다**
→ PHP가 안 켜진 상태입니다. 1단계에서 PHP 설치와 Web Station 설정을 다시 확인하세요.

**Q. 화면은 잘 열리는데 저장만 실패합니다** ← 가장 흔한 문제
→ `http` 계정의 쓰기 권한이 없는 경우입니다. 먼저 원인을 확인하세요.

```
http://192.168.0.37/brand/save.php?check=1
```

`"현재폴더_쓰기가능": "아니오"` 로 나오면 확정입니다. 이렇게 고칩니다.

1. File Station → **`web` 폴더** 우클릭 → 속성 → **권한** 탭
2. `http` 항목 선택 → 편집 (없으면 **생성** → 필터 아이콘 → **시스템 내부 사용자** → `http`)
3. **읽기 + 쓰기 전체 체크**
4. **「이 폴더, 하위 폴더 및 파일에 적용」 체크** ← 이게 핵심
5. 저장 후 위 주소를 다시 열어 `"예"` 로 바뀌었는지 확인

그래도 `"아니오"` 면 폴더 권한이 꼬인 것이니, `brand` 폴더를 지우고
**File Station으로 다시 만든 뒤** 파일을 올리세요.

**Q. "NAS 저장 실패 (404)"가 뜹니다**
→ `save.php`가 `brand.html`과 다른 폴더에 있습니다. 같은 폴더로 옮기세요.

**Q. 두 사람이 동시에 저장하면 어떻게 되나요?**
→ 파일이 깨지지는 않습니다(잠금 처리됨). 다만 **나중에 저장한 사람의 값이 남습니다.**
   같은 달 같은 브랜드를 동시에 편집하는 일은 피해 주세요.

**Q. 지금 우리 NAS가 인터넷에 열려 있는 상태인가요?**
→ `netformrnd.synology.me`라는 DDNS 주소로 접속이 되고 있다면,
   **WebDAV 포트(5006)가 외부 인터넷에 열려 있을 가능성이 높습니다.**
   DSM → **제어판 → 외부 액세스 → 라우터 구성**에서 어떤 포트가 열려 있는지 한번 확인해 보세요.
   쓰지 않는 포트가 열려 있다면 닫는 편이 안전합니다.
   또한 **제어판 → 보안 → 계정**에서 자동 차단(로그인 실패 시 IP 차단)을 켜두시길 권합니다.

**Q. 외부(집)에서도 보고 싶습니다**
→ 지금 설정은 **사내망 전용**입니다. 외부 공개는 보안 설정(HTTPS, 방화벽, 계정 권한)이
   추가로 필요하니, 필요해지면 그때 따로 안내해 드리겠습니다.
   **NAS를 아무 설정 없이 인터넷에 열어두면 위험합니다.**
