# 브랜드 대시보드 — NAS 연결 설치 안내서

코드를 몰라도 따라 할 수 있게 썼습니다. **위에서부터 순서대로** 하시면 됩니다.

---

## 이게 무슨 작업인가요?

지금 대시보드는 데이터를 **내 브라우저 안에만** 저장합니다.
그래서 다른 PC에서 열면 빈 화면이고, 브라우저 기록을 지우면 데이터가 날아갑니다.

NAS에 올리면 **회사 안 어느 PC에서 접속해도 같은 데이터**를 보게 됩니다.

```
[지금]   내 PC 브라우저 ── 데이터가 여기 갇혀 있음

[NAS 연결 후]
   김대리 PC ┐
   박과장 PC ┼─→  NAS의 data/brand-data.json  (하나뿐인 원본)
   회의실 PC ┘
```

---

## 0단계. 우리 NAS 확인 — ✅ 완료

RaiDrive 화면으로 확인이 끝났습니다. 이 단계는 건너뛰셔도 됩니다.

| 항목 | 확인된 값 | 어떻게 알았나 |
|---|---|---|
| 제조사 | **시놀로지 (Synology)** | 주소가 `synology.me` (시놀로지 전용 DDNS) |
| 외부 주소 | `netformrnd.synology.me` | RaiDrive 주소 칸 |
| 사용 중인 기능 | **WebDAV** (포트 5006 = WebDAV HTTPS) | RaiDrive 포트 칸 |
| 보안 | TLS 1.3 적용됨 | RaiDrive TLS/SSL 칸 |
| 현재 연결 | RaiDrive로 `Z:`, `Y:` 드라이브 연결 중 | RaiDrive 좌측 목록 |
| **내부 IP** | **`192.168.0.37`** | DSM 제어판 → 네트워크 |
| Web Station | **이미 설치됨** (포트 80/443 동작 중) | 패키지 센터 → 설치됨 |

즉 **아래 시놀로지 기준 안내를 그대로 따라가시면 됩니다.**

### DSM 관리자 화면 접속 주소
```
https://netformrnd.synology.me:5001
```
(5001은 DSM 관리자 페이지 기본 포트입니다. 사내에서는 `https://[NAS내부IP]:5001` 도 됩니다)

> **참고 — WebDAV로는 안 되나요?**
> 이미 WebDAV(5006)가 켜져 있지만, 대시보드는 브라우저에서 실행되기 때문에
> WebDAV에 직접 저장할 수 없습니다(브라우저 보안 정책이 막습니다).
> 그래서 아래처럼 **Web Station**을 추가로 켜는 방식이 필요합니다.
> 기존 WebDAV 설정은 그대로 두시면 되고, 서로 영향을 주지 않습니다.

## 1단계. 웹 서버 기능 켜기 — ✅ 설치 완료, PHP만 확인

**Web Station은 이미 설치되어 동작 중입니다** (기본 포털 / 포트 80·443 / 상태 "보통").
따라서 설치는 건너뛰고, **PHP가 켜져 있는지만** 확인하면 됩니다.

### 1-1. PHP 패키지 설치
Web Station → 왼쪽 **스크립트 언어 설정** → PHP 탭을 보면
"사용 가능한 PHP 패키지가 없습니다"라고 나옵니다. (초기 상태로, 정상입니다)

**패키지 센터**를 열고 `php`로 검색해 **가장 높은 버전 하나**를 설치합니다.
(예: `PHP 8.2`. `PHP 7.4` 같은 낮은 버전은 설치할 필요 없습니다)

### 1-2. PHP 프로필 만들기 ⚠️ 빠뜨리기 쉬운 단계
패키지를 설치했다고 바로 쓸 수 있는 게 아니라, **프로필을 만들어야** 합니다.

Web Station → **스크립트 언어 설정** → PHP 탭 → **`생성`** 버튼
- 프로필 이름: 아무거나 (예: `brand`)
- 나머지는 **기본값 그대로 두고 저장**

### 1-3. 기본 서버에 PHP 연결
Web Station → 왼쪽 **웹 서비스** → `기본 서버` 선택 → **편집**
- **백엔드 서버**: Apache 또는 Nginx (무엇이든 상관없습니다)
- **PHP**: 1-2에서 만든 프로필 선택 → **저장**

> 이 3단계를 마치면 NAS 설정은 끝입니다. 이후는 파일 복사뿐입니다.

> `web` 공유 폴더는 Web Station 설치 시 이미 만들어져 있습니다.

## 2단계. 파일 올리기 (5분)

**File Station**을 열고 `web` 폴더 안에 `brand`라는 폴더를 새로 만든 뒤,
아래 3개 파일을 그 안에 올립니다.

| 올릴 파일 | 어디 있나요 |
|---|---|
| `brand.html` | 이 저장소 맨 위 |
| `load.php` | 이 저장소의 `nas` 폴더 |
| `save.php` | 이 저장소의 `nas` 폴더 |
| `files.php` | 이 저장소의 `nas` 폴더 (자료 파일 업로드·다운로드) |
| `deploy.sh` | 이 저장소의 `nas` 폴더 (자동 업데이트) |

**주의:** `nas` 폴더째로 올리지 말고, **파일 3개가 같은 폴더에 나란히** 있어야 합니다.

> ## ⚠️ 반드시 File Station으로 만들고 올리세요
>
> 윈도우 탐색기(RaiDrive `Z:` 드라이브)로 **폴더를 만들면 저장 기능이 고장납니다.**
> 탐색기로 만든 폴더에는 PHP 실행 계정(`http`)의 **쓰기 권한이 들어가지 않기** 때문입니다.
>
> 증상이 헷갈립니다 — **화면은 잘 열리는데 저장만 실패**합니다.
> 웹서버는 파일을 읽기만 하면 되니 읽기 권한만으로 화면은 멀쩡히 뜨거든요.
>
> 파일을 **덮어쓰는 것**은 탐색기로 해도 괜찮습니다. 문제가 되는 건 **폴더 생성**입니다.

```
web/
└── brand/
    ├── brand.html
    ├── load.php
    ├── save.php
    ├── files.php
    ├── deploy.sh
    └── data/                  ← 처음 저장할 때 자동으로 생깁니다
        ├── brand-data.json    ← 입력한 글자 (브랜드·자동화·히스토리·메모·프롬프트)
        ├── backup-2026-09-01.json
        └── files/                    ← 자료 탭에 올린 실제 파일
            ├── POUR공법/
            │   ├── 제품 카탈로그 2026.pdf
            │   └── 단가표.xlsx
            └── 아파트스퀘어/
                └── 브랜드 가이드.pdf
```

> 파일은 **브랜드 이름 폴더에 원래 이름 그대로** 저장됩니다.
> 탐색기(`Z:\web\brand\data\files\`)에서 열어도 바로 알아볼 수 있고,
> 이 폴더 자체가 정리된 자료 보관함이 됩니다.
>
> ⚠️ **탐색기에서 파일 이름을 바꾸거나 옮기지 마세요.** 대시보드의 다운로드 링크가 끊어집니다.
> 정리는 대시보드에서 하시고, 탐색기는 보는 용도로만 쓰세요.

## 3단계. 대시보드 설정 — ✅ 할 일 없음

예전에는 `brand.html`을 열어 `STORAGE_MODE`를 직접 고쳐야 했지만,
**이제는 자동으로 판단합니다.** 파일을 열어볼 필요가 없습니다.

| 어떻게 열었나 | 저장 위치 | 화면 배지 |
|---|---|---|
| `http://192.168.0.37/brand/brand.html` | **NAS** (모두 공유) | 🟢 NAS 공유 저장 |
| 파일을 더블클릭 (`file:///C:/...`) | 이 브라우저에만 | 🟡 이 브라우저에만 저장 |

즉 **NAS 주소로 열면 자동으로 NAS에 저장**됩니다.

## 4단계. 접속해서 확인하기

사내망 PC에서 브라우저를 열고 아래 주소로 들어갑니다.

```
사내망 (이 주소를 직원들에게 공유하세요):

    http://192.168.0.37/brand/brand.html
```

즐겨찾기에 등록해두면 편합니다.

> Web Station의 기본 포트는 **80(HTTP) / 443(HTTPS)** 입니다.
> DSM 관리자 포트(5001)나 WebDAV 포트(5006)와는 다른 포트이니 헷갈리지 마세요.

화면 오른쪽 위 배지가 **🟢 NAS 공유 저장**으로 바뀌면 성공입니다.

이제 숫자를 입력하고 **[저장]**을 누른 뒤, **다른 PC에서 같은 주소로 접속**해 보세요.
같은 숫자가 보이면 연결이 제대로 된 것입니다.

## 대시보드를 수정할 때 (앞으로 계속 쓰게 될 절차)

기능을 추가하거나 화면을 바꾸면, 아래 3단계로 반영합니다. **30초면 됩니다.**

1. 저장소에서 **`brand.html` 하나만** 새로 받습니다
2. NAS의 `web/brand/` 폴더에 **덮어쓰기**
3. 브라우저에서 **`Ctrl` + `F5`** (강력 새로고침)

### 데이터는 절대 안 날아갑니다

`brand.html`과 데이터 파일은 **완전히 별개**이기 때문입니다.

```
web/brand/
├── brand.html             ← 화면 틀.   수정 시 이것만 교체
├── load.php  save.php     ← 거의 안 바뀜
└── data/
    └── brand-data.json    ← 입력한 숫자. 교체와 무관, 그대로 유지
```

`brand.html`을 100번 교체해도 `data/` 폴더는 건드리지 않으므로 데이터는 그대로입니다.

> **불안하면**: 교체 전에 대시보드에서 **[📤 내보내기]** 한 번 눌러두세요.
> 문제가 생겨도 **[📥 가져오기]** 로 되돌릴 수 있습니다.

## (선택) 구글시트 문의 기록 연결하기

구글시트의 문의 기록을 브랜드별 「📞 문의」 탭에 표시하는 기능입니다.
**시트를 외부에 공개하지 않아도 됩니다.** n8n이 시트를 읽어 NAS로 보내는 방식입니다.

### 왜 이 방식인가

시트를 「웹에 게시」하면 주소를 아는 사람은 누구나 볼 수 있게 됩니다.
문의 기록에는 고객명과 연락처가 들어있으므로 그 방식은 쓰지 않습니다.

### 준비 — 시트 조건

브랜드를 구분하는 열이 있어야 합니다. 열 이름은 `브랜드` / `brand` / `브랜드명` 중 하나면 됩니다.
값은 대시보드의 브랜드 이름과 같아야 합니다. (띄어쓰기 차이는 무시합니다)

| 날짜 | **브랜드** | 고객명 | 연락처 | 공종 | 유입 | 내용 | 상태 |
|---|---|---|---|---|---|---|---|
| 2026-08-28 | 아파트스퀘어 | 김관리 | 010-... | 옥상방수 | 전화 | 옥상 누수 견적 | 현장방문예정 |

나머지 열은 자유입니다. **있는 열을 그대로 표로 보여줍니다.**

### n8n 설정 (기존 워크플로는 건드리지 않습니다)

**새 워크플로를 하나 만드세요.** 기존 자동화와 완전히 별개로 돌아갑니다.

```
[Schedule Trigger]  매일 1회
        ↓
[Google Sheets]  Get Rows
        ↓
[Code]  아래 코드
        ↓
[HTTP Request]  POST
```

**Code 노드**
```javascript
return [{ json: {
  source: 'n8n-google-sheets',
  token: '',                                  // config.php 에 토큰을 넣었다면 같은 값
  rows: $input.all().map(i => i.json)
}}];
```

**HTTP Request 노드**
| 항목 | 값 |
|---|---|
| Method | `POST` |
| URL | `http://192.168.0.37/brand/inquiries.php?action=push` |
| Body Content Type | `JSON` |
| Body | `{{ $json }}` |

### 확인
```
http://192.168.0.37/brand/inquiries.php?action=check
```
`"보관건수"` 와 `"브랜드별"` 이 나오면 성공입니다.

### 안전장치

- **보낼 때마다 전체를 교체**합니다. 시트에서 지운 행은 대시보드에서도 사라집니다
- 내용이 전부 빈 행은 버립니다
- 파일 잠금을 걸어 동시에 들어와도 깨지지 않습니다
- 한 번에 최대 20,000건
- 대시보드에서는 **읽기 전용**입니다. 수정은 원본 시트에서 하세요
- 이 기능은 `data/inquiries.json` 하나만 씁니다. 다른 데이터와 섞이지 않습니다

### 토큰 (선택)

아무나 밀어넣지 못하게 하려면 `config.sample.php` 를 `config.php` 로 복사하고
`push_token` 에 아무 문자열이나 넣으세요. n8n Code 노드의 `token` 에 같은 값을 넣으면 됩니다.
비워두면 사내망 전제로 검사하지 않습니다.

## 파일이 빠졌거나 꼬였을 때 — 복구 주소

`save.php` 하나만 살아 있으면, 나머지 파일을 스스로 받아옵니다.

```
http://192.168.0.37/brand/save.php?action=bootstrap
```

브라우저로 이 주소를 열면 `brand.html`, `load.php`, `files.php`, `deploy.sh` 를
GitHub에서 직접 받아 제자리에 놓습니다. 결과가 이렇게 나오면 성공입니다.

```json
{ "ok": true, "결과": { "brand.html": "설치 완료", "deploy.sh": "설치 완료" } }
```

이미 최신이면 `"이미 최신"` 으로 표시되고 아무것도 바꾸지 않습니다.
**파일을 손으로 옮길 일이 없도록** 만들어 둔 장치이니, 뭔가 꼬이면 이 주소부터 열어보세요.

## ⚠️ 파일 업로드 용량 한도 올리기 (자료 탭을 쓰려면 필수)

PHP는 기본값이 **업로드 2MB / 요청 8MB** 로 매우 작습니다.
이 상태로는 카탈로그 PDF 하나도 못 올립니다. **한 번만 올려두면 됩니다.**

### 지금 한도 확인
```
http://192.168.0.37/brand/files.php?action=check
```
`"php업로드한도": "2M"` 처럼 나오면 아래대로 바꾸세요.

### 바꾸는 법
1. **Web Station → 스크립트 언어 설정 → PHP 탭**
2. `Default Profile` 선택 → **편집**
3. **「코어」 탭** 으로 이동
4. 아래 두 값을 찾아 수정

| 항목 | 권장값 |
|---|---|
| `upload_max_filesize` | `200M` |
| `post_max_size` | `210M` |

> `post_max_size`는 `upload_max_filesize`보다 **조금 더 크게** 잡아야 합니다.
> 파일 외에 다른 정보도 같이 전송되기 때문입니다.

5. **저장** → 위 확인 주소를 다시 열어 `200M` 으로 바뀌었는지 확인

`memory_limit`이 `256M` 이상인지도 함께 봐두면 좋습니다.

## (선택) 자동 업데이트 — 파일 복사를 아예 없애기

수정할 때마다 파일을 옮기는 게 번거로우면, **NAS가 스스로 최신 파일을 받아오게** 할 수 있습니다.
한 번만 설정하면 그 뒤로는 손댈 일이 없습니다.

```
Claude가 수정 → GitHub에 올림 → NAS가 정해진 시간에 자동으로 받아옴 → 새로고침만
```

### 설정 방법 (10분, 한 번만)

**1.** `deploy.sh` 파일을 NAS의 `web/brand/` 폴더에 올립니다 (다른 파일과 같은 위치)

**2.** DSM → **제어판** → **작업 스케줄러** → **생성** → **예약된 작업** → **사용자 정의 스크립트**

**3.** 아래처럼 설정합니다

| 항목 | 값 |
|---|---|
| 작업 이름 | `브랜드 대시보드 업데이트` |
| 사용자 | `root` |
| 일정 | 매일 / 원하는 시간 (또는 몇 시간마다) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/deploy.sh` |

**4.** 만든 작업을 선택하고 **실행** 버튼으로 한 번 돌려봅니다.
`web/brand/deploy.log` 파일에 `갱신: brand.html` 같은 기록이 남으면 성공입니다.

### 스크립트 스스로 최신화됩니다

`deploy.sh` 자체가 바뀌어도 다음 실행 때 자동으로 새 버전으로 교체됩니다.
**처음 한 번만** NAS에 올려두면, 이후로는 손댈 일이 없습니다.

### 이 스크립트의 안전장치

파일을 자동으로 덮어쓰는 일이라, 아래를 확인한 뒤에만 교체합니다.

- 내려받은 파일이 **비어 있거나 깨져 있으면 교체하지 않고** 기존 파일을 그대로 둡니다
- **내용이 바뀐 파일만** 교체합니다 (매번 덮어쓰지 않음)
- `data/` 폴더(입력한 숫자)는 **절대 건드리지 않습니다**
- 네트워크 오류로 실패해도 기존 화면은 멀쩡히 동작합니다

### 주의

자동이라는 건 **검토 없이 반영된다는 뜻**이기도 합니다.
급하게 확인이 필요한 변경이라면 자동 실행을 기다리지 말고,
작업 스케줄러에서 **[실행]** 버튼을 눌러 즉시 반영하세요.

## 인터넷 없는 사내망에서 차트 보이게 하기

회사 네트워크가 외부 인터넷을 막아둔 경우, 그래프 자리에
"차트 라이브러리를 불러오지 못했습니다"라고 뜹니다. **숫자와 표는 정상 동작**하며,
그래프만 안 보이는 상태입니다. 아래처럼 고칩니다.

1. 인터넷이 되는 PC에서 이 주소를 엽니다:
   `https://cdn.jsdelivr.net/npm/chart.js@4/dist/chart.umd.min.js`
2. `Ctrl+S`로 파일을 저장합니다.
3. 파일 이름을 정확히 **`chart.umd.min.js`** 로 바꿉니다.
4. NAS의 `web/brand/` 안에 **`vendor`** 폴더를 만들고 그 안에 넣습니다.

```
web/brand/
├── brand.html
├── load.php
├── save.php
└── vendor/
    └── chart.umd.min.js
```

새로고침하면 그래프가 나옵니다. (이후로는 인터넷 없이도 계속 동작합니다)

## 백업 — 꼭 해두세요

NAS 연결 후에는 `data/brand-data.json` **파일 하나가 유일한 원본**입니다.
이게 사라지면 데이터도 사라집니다.

- `save.php`가 **하루에 한 번 자동 백업**을 만듭니다 (`data/backup-2026-08-31.json`)
- 여기에 더해, NAS 관리자 화면에서 `web` 폴더에 대해
  **스냅샷(Snapshot Replication)** 또는 **Hyper Backup**을 켜두시길 권합니다.
- 중요한 시점에는 대시보드의 **[📤 내보내기]** 버튼으로 내 PC에도 한 부 받아두세요.

## 자주 겪는 문제

**Q. 접속하면 화면 대신 코드 글자가 잔뜩 나옵니다**
→ PHP가 안 켜진 상태입니다. 1단계에서 PHP 설치와 Web Station 설정을 다시 확인하세요.

**Q. 화면은 잘 열리는데 저장만 실패합니다** ← 가장 흔한 문제
→ `http` 계정의 쓰기 권한이 없는 경우입니다. 먼저 원인을 확인하세요.

```
http://192.168.0.37/brand/save.php?check=1
```

`"현재폴더_쓰기가능": "아니오"` 로 나오면 확정입니다. 이렇게 고칩니다.

1. File Station → **`web` 폴더** 우클릭 → 속성 → **권한** 탭
2. `http` 항목 선택 → 편집 (없으면 **생성** → 필터 아이콘 → **시스템 내부 사용자** → `http`)
3. **읽기 + 쓰기 전체 체크**
4. **「이 폴더, 하위 폴더 및 파일에 적용」 체크** ← 이게 핵심
5. 저장 후 위 주소를 다시 열어 `"예"` 로 바뀌었는지 확인

그래도 `"아니오"` 면 폴더 권한이 꼬인 것이니, `brand` 폴더를 지우고
**File Station으로 다시 만든 뒤** 파일을 올리세요.

**Q. "NAS 저장 실패 (404)"가 뜹니다**
→ `save.php`가 `brand.html`과 다른 폴더에 있습니다. 같은 폴더로 옮기세요.

**Q. 두 사람이 동시에 저장하면 어떻게 되나요?**
→ 파일이 깨지지는 않습니다(잠금 처리됨). 다만 **나중에 저장한 사람의 값이 남습니다.**
   같은 달 같은 브랜드를 동시에 편집하는 일은 피해 주세요.

**Q. 지금 우리 NAS가 인터넷에 열려 있는 상태인가요?**
→ `netformrnd.synology.me`라는 DDNS 주소로 접속이 되고 있다면,
   **WebDAV 포트(5006)가 외부 인터넷에 열려 있을 가능성이 높습니다.**
   DSM → **제어판 → 외부 액세스 → 라우터 구성**에서 어떤 포트가 열려 있는지 한번 확인해 보세요.
   쓰지 않는 포트가 열려 있다면 닫는 편이 안전합니다.
   또한 **제어판 → 보안 → 계정**에서 자동 차단(로그인 실패 시 IP 차단)을 켜두시길 권합니다.

**Q. 외부(집)에서도 보고 싶습니다**
→ 지금 설정은 **사내망 전용**입니다. 외부 공개는 보안 설정(HTTPS, 방화벽, 계정 권한)이
   추가로 필요하니, 필요해지면 그때 따로 안내해 드리겠습니다.
   **NAS를 아무 설정 없이 인터넷에 열어두면 위험합니다.**
