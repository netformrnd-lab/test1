# 브랜드 대시보드 — NAS 연결 설치 안내서

코드를 몰라도 따라 할 수 있게 썼습니다. **위에서부터 순서대로** 하시면 됩니다.

---

## 이게 무슨 작업인가요?

지금 대시보드는 데이터를 **내 브라우저 안에만** 저장합니다.
그래서 다른 PC에서 열면 빈 화면이고, 브라우저 기록을 지우면 데이터가 날아갑니다.

NAS에 올리면 **회사 안 어느 PC에서 접속해도 같은 데이터**를 보게 됩니다.

```
[지금]   내 PC 브라우저 ── 데이터가 여기 갇혀 있음

[NAS 연결 후]
   김대리 PC ┐
   박과장 PC ┼─→  NAS의 data/brand-data.json  (하나뿐인 원본)
   회의실 PC ┘
```

---

## 0단계. 우리 NAS 확인 — ✅ 완료

RaiDrive 화면으로 확인이 끝났습니다. 이 단계는 건너뛰셔도 됩니다.

| 항목 | 확인된 값 | 어떻게 알았나 |
|---|---|---|
| 제조사 | **시놀로지 (Synology)** | 주소가 `synology.me` (시놀로지 전용 DDNS) |
| 외부 주소 | `netformrnd.synology.me` | RaiDrive 주소 칸 |
| 사용 중인 기능 | **WebDAV** (포트 5006 = WebDAV HTTPS) | RaiDrive 포트 칸 |
| 보안 | TLS 1.3 적용됨 | RaiDrive TLS/SSL 칸 |
| 현재 연결 | RaiDrive로 `Z:`, `Y:` 드라이브 연결 중 | RaiDrive 좌측 목록 |
| **내부 IP** | **`192.168.0.37`** | DSM 제어판 → 네트워크 |
| Web Station | **이미 설치됨** (포트 80/443 동작 중) | 패키지 센터 → 설치됨 |

즉 **아래 시놀로지 기준 안내를 그대로 따라가시면 됩니다.**

### DSM 관리자 화면 접속 주소
```
https://netformrnd.synology.me:5001
```
(5001은 DSM 관리자 페이지 기본 포트입니다. 사내에서는 `https://[NAS내부IP]:5001` 도 됩니다)

> **참고 — WebDAV로는 안 되나요?**
> 이미 WebDAV(5006)가 켜져 있지만, 대시보드는 브라우저에서 실행되기 때문에
> WebDAV에 직접 저장할 수 없습니다(브라우저 보안 정책이 막습니다).
> 그래서 아래처럼 **Web Station**을 추가로 켜는 방식이 필요합니다.
> 기존 WebDAV 설정은 그대로 두시면 되고, 서로 영향을 주지 않습니다.

## 1단계. 웹 서버 기능 켜기 — ✅ 설치 완료, PHP만 확인

**Web Station은 이미 설치되어 동작 중입니다** (기본 포털 / 포트 80·443 / 상태 "보통").
따라서 설치는 건너뛰고, **PHP가 켜져 있는지만** 확인하면 됩니다.

### 1-1. PHP 패키지 설치
Web Station → 왼쪽 **스크립트 언어 설정** → PHP 탭을 보면
"사용 가능한 PHP 패키지가 없습니다"라고 나옵니다. (초기 상태로, 정상입니다)

**패키지 센터**를 열고 `php`로 검색해 **가장 높은 버전 하나**를 설치합니다.
(예: `PHP 8.2`. `PHP 7.4` 같은 낮은 버전은 설치할 필요 없습니다)

### 1-2. PHP 프로필 만들기 ⚠️ 빠뜨리기 쉬운 단계
패키지를 설치했다고 바로 쓸 수 있는 게 아니라, **프로필을 만들어야** 합니다.

Web Station → **스크립트 언어 설정** → PHP 탭 → **`생성`** 버튼
- 프로필 이름: 아무거나 (예: `brand`)
- 나머지는 **기본값 그대로 두고 저장**

### 1-3. 기본 서버에 PHP 연결
Web Station → 왼쪽 **웹 서비스** → `기본 서버` 선택 → **편집**
- **백엔드 서버**: Apache 또는 Nginx (무엇이든 상관없습니다)
- **PHP**: 1-2에서 만든 프로필 선택 → **저장**

> 이 3단계를 마치면 NAS 설정은 끝입니다. 이후는 파일 복사뿐입니다.

> `web` 공유 폴더는 Web Station 설치 시 이미 만들어져 있습니다.

## 2단계. 파일 올리기 (5분)

**File Station**을 열고 `web` 폴더 안에 `brand`라는 폴더를 새로 만든 뒤,
아래 3개 파일을 그 안에 올립니다.

| 올릴 파일 | 어디 있나요 |
|---|---|
| `brand.html` | 이 저장소 맨 위 |
| `load.php` | 이 저장소의 `nas` 폴더 |
| `save.php` | 이 저장소의 `nas` 폴더 |
| `files.php` | 이 저장소의 `nas` 폴더 (자료 파일 업로드·다운로드) |
| `deploy.sh` | 이 저장소의 `nas` 폴더 (자동 업데이트) |

**주의:** `nas` 폴더째로 올리지 말고, **파일 3개가 같은 폴더에 나란히** 있어야 합니다.

> ## ⚠️ 반드시 File Station으로 만들고 올리세요
>
> 윈도우 탐색기(RaiDrive `Z:` 드라이브)로 **폴더를 만들면 저장 기능이 고장납니다.**
> 탐색기로 만든 폴더에는 PHP 실행 계정(`http`)의 **쓰기 권한이 들어가지 않기** 때문입니다.
>
> 증상이 헷갈립니다 — **화면은 잘 열리는데 저장만 실패**합니다.
> 웹서버는 파일을 읽기만 하면 되니 읽기 권한만으로 화면은 멀쩡히 뜨거든요.
>
> 파일을 **덮어쓰는 것**은 탐색기로 해도 괜찮습니다. 문제가 되는 건 **폴더 생성**입니다.

```
web/
└── brand/
    ├── brand.html
    ├── load.php
    ├── save.php
    ├── files.php
    ├── deploy.sh
    └── data/                  ← 처음 저장할 때 자동으로 생깁니다
        ├── brand-data.json    ← 입력한 글자 (브랜드·자동화·히스토리·메모·프롬프트)
        ├── backup-2026-09-01.json
        └── files/                    ← 자료 탭에 올린 실제 파일
            ├── POUR공법/
            │   ├── 제품 카탈로그 2026.pdf
            │   └── 단가표.xlsx
            └── 아파트스퀘어/
                └── 브랜드 가이드.pdf
```

> 파일은 **브랜드 이름 폴더에 원래 이름 그대로** 저장됩니다.
> 탐색기(`Z:\web\brand\data\files\`)에서 열어도 바로 알아볼 수 있고,
> 이 폴더 자체가 정리된 자료 보관함이 됩니다.
>
> ⚠️ **탐색기에서 파일 이름을 바꾸거나 옮기지 마세요.** 대시보드의 다운로드 링크가 끊어집니다.
> 정리는 대시보드에서 하시고, 탐색기는 보는 용도로만 쓰세요.

## 3단계. 대시보드 설정 — ✅ 할 일 없음

예전에는 `brand.html`을 열어 `STORAGE_MODE`를 직접 고쳐야 했지만,
**이제는 자동으로 판단합니다.** 파일을 열어볼 필요가 없습니다.

| 어떻게 열었나 | 저장 위치 | 화면 배지 |
|---|---|---|
| `http://192.168.0.37/brand/brand.html` | **NAS** (모두 공유) | 🟢 NAS 공유 저장 |
| 파일을 더블클릭 (`file:///C:/...`) | 이 브라우저에만 | 🟡 이 브라우저에만 저장 |

즉 **NAS 주소로 열면 자동으로 NAS에 저장**됩니다.

## 4단계. 접속해서 확인하기

사내망 PC에서 브라우저를 열고 아래 주소로 들어갑니다.

```
사내망 (이 주소를 직원들에게 공유하세요):

    http://192.168.0.37/brand/brand.html
```

즐겨찾기에 등록해두면 편합니다.

> Web Station의 기본 포트는 **80(HTTP) / 443(HTTPS)** 입니다.
> DSM 관리자 포트(5001)나 WebDAV 포트(5006)와는 다른 포트이니 헷갈리지 마세요.

화면 오른쪽 위 배지가 **🟢 NAS 공유 저장**으로 바뀌면 성공입니다.

이제 숫자를 입력하고 **[저장]**을 누른 뒤, **다른 PC에서 같은 주소로 접속**해 보세요.
같은 숫자가 보이면 연결이 제대로 된 것입니다.

## 대시보드를 수정할 때 (앞으로 계속 쓰게 될 절차)

기능을 추가하거나 화면을 바꾸면, 아래 3단계로 반영합니다. **30초면 됩니다.**

1. 저장소에서 **`brand.html` 하나만** 새로 받습니다
2. NAS의 `web/brand/` 폴더에 **덮어쓰기**
3. 브라우저에서 **`Ctrl` + `F5`** (강력 새로고침)

### 데이터는 절대 안 날아갑니다

`brand.html`과 데이터 파일은 **완전히 별개**이기 때문입니다.

```
web/brand/
├── brand.html             ← 화면 틀.   수정 시 이것만 교체
├── load.php  save.php     ← 거의 안 바뀜
└── data/
    └── brand-data.json    ← 입력한 숫자. 교체와 무관, 그대로 유지
```

`brand.html`을 100번 교체해도 `data/` 폴더는 건드리지 않으므로 데이터는 그대로입니다.

> **불안하면**: 교체 전에 대시보드에서 **[📤 내보내기]** 한 번 눌러두세요.
> 문제가 생겨도 **[📥 가져오기]** 로 되돌릴 수 있습니다.

## (선택) 구글시트 문의 기록 연결하기

구글시트의 문의 기록을 브랜드별 「📞 문의」 탭에 표시하는 기능입니다.
**시트를 외부에 공개하지 않아도 됩니다.** n8n이 시트를 읽어 NAS로 보내는 방식입니다.

### 왜 이 방식인가

시트를 「웹에 게시」하면 주소를 아는 사람은 누구나 볼 수 있게 됩니다.
문의 기록에는 고객명과 연락처가 들어있으므로 그 방식은 쓰지 않습니다.

### 준비 — 시트 조건

브랜드를 구분하는 열이 있어야 합니다. 열 이름은 `브랜드` / `brand` / `브랜드명` 중 하나면 됩니다.
값은 대시보드의 브랜드 이름과 같아야 합니다. (띄어쓰기 차이는 무시합니다)

| 날짜 | **브랜드** | 고객명 | 연락처 | 공종 | 유입 | 내용 | 상태 |
|---|---|---|---|---|---|---|---|
| 2026-08-28 | 아파트스퀘어 | 김관리 | 010-... | 옥상방수 | 전화 | 옥상 누수 견적 | 현장방문예정 |

나머지 열은 자유입니다. **있는 열을 그대로 표로 보여줍니다.**

### 브랜드마다 시트가 다를 때

시트를 **여러 개** 연결할 수 있습니다. 브랜드마다 시트가 따로 있어도 됩니다.

```
브랜드 → 📞 문의 → [🔗 시트 관리]

🔗 연결된 구글시트                브랜드마다 다른 시트를 붙일 수 있습니다

  통합 시트          [시트의 브랜드 열 사용]     [브랜드] [연결 해제]
  https://docs.google.com/…/pub?output=csv

  슈어포인트 문의     [슈어포인트 전용]          [브랜드] [연결 해제]
  https://docs.google.com/…/pub?output=csv

  [＋ 시트 연결]  [↻ 지금 가져오기]
```

시트를 추가할 때 **어느 브랜드 것인지** 물어봅니다.

- **0 (시트의 브랜드 열 사용)** — 시트에 「브랜드」 열이 있는 경우.
  한 시트에 여러 브랜드가 섞여 있어도 열을 보고 나눕니다.
- **브랜드 번호** — 그 브랜드 전용 시트인 경우.
  **「브랜드」 열이 없어도 됩니다.** 열 이름이 달라도(등록일·현장·문의유형 …) 상관없습니다.

여러 시트를 합쳐서 보여주며, 한 시트를 못 가져와도 나머지는 그대로 나옵니다
(실패한 시트는 이유와 함께 표시됩니다).

### 방법 1 — 시트 주소 연결 (한 번만 설정, 이후 자동)

1. 구글시트 → **파일 → 공유 → 웹에 게시** → 형식 **쉼표로 구분된 값(.csv)** → 게시
2. 나온 주소를 복사
3. 대시보드 → **📞 문의** 탭 → **[🔗 시트 연결]** → 주소 붙여넣기

이후로는 두 가지 방식으로 알아서 최신이 됩니다.

| 언제 | 무엇이 | 조건 |
|---|---|---|
| **10분마다** | NAS 작업 스케줄러가 시트를 가져옴 | 아무도 안 봐도 계속 동작 |
| 문의 탭을 열 때 | 마지막 갱신이 5분 넘었으면 다시 가져옴 | 화면을 볼 때 최신 보장 |

지금 당장 반영하려면 **[↻ 시트에서 가져오기]** 를 누르세요.

> ⚠️ 「웹에 게시」한 주소는 **주소를 아는 사람이면 누구나 볼 수 있습니다.**
> 고객 이름·연락처가 들어있다면 그 점을 감안하고 쓰셔야 합니다.
> 게시를 중단하려면 같은 화면에서 「게시 중지」를 누르면 됩니다.

### 방법 2 — CSV 올리기 (설정 없이 바로)

1. 구글시트에서 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**
2. 대시보드 → 아무 브랜드 → **📞 문의** 탭 → **[📥 시트 CSV 올리기]**

올릴 때마다 **전체가 교체**되므로, 항상 최신 시트를 받아 올리시면 됩니다.
시트를 외부에 공개하지 않아도 되고, n8n도 필요 없습니다.

### 방법 3 — n8n으로 자동화 (기존 워크플로는 건드리지 않습니다)

**새 워크플로를 하나 만드세요.** 기존 자동화와 완전히 별개로 돌아갑니다.

```
[Schedule Trigger]  매일 1회
        ↓
[Google Sheets]  Get Rows
        ↓
[Code]  아래 코드
        ↓
[HTTP Request]  POST
```

**Code 노드**
```javascript
return [{ json: {
  source: 'n8n-google-sheets',
  token: '',                                  // config.php 에 토큰을 넣었다면 같은 값
  rows: $input.all().map(i => i.json)
}}];
```

**HTTP Request 노드**
| 항목 | 값 |
|---|---|
| Method | `POST` |
| URL | `http://192.168.0.37/brand/inquiries.php?action=push` |
| Body Content Type | `JSON` |
| Body | `{{ $json }}` |

### 확인
```
http://192.168.0.37/brand/inquiries.php?action=check
```
`"보관건수"` 와 `"브랜드별"` 이 나오면 성공입니다.

### 안전장치

- **보낼 때마다 전체를 교체**합니다. 시트에서 지운 행은 대시보드에서도 사라집니다
- 내용이 전부 빈 행은 버립니다
- 파일 잠금을 걸어 동시에 들어와도 깨지지 않습니다
- 한 번에 최대 20,000건
- 대시보드에서는 **읽기 전용**입니다. 수정은 원본 시트에서 하세요
- 이 기능은 `data/inquiries.json` 하나만 씁니다. 다른 데이터와 섞이지 않습니다

### 토큰 (선택)

아무나 밀어넣지 못하게 하려면 `config.sample.php` 를 `config.php` 로 복사하고
`push_token` 에 아무 문자열이나 넣으세요. n8n Code 노드의 `token` 에 같은 값을 넣으면 됩니다.
비워두면 사내망 전제로 검사하지 않습니다.

## (선택) NAS 공유폴더 파일 찾기

수만 개 파일이 흩어져 있어도 **대시보드에서 이름으로 찾을 수 있게** 하는 기능입니다.
**파일을 옮기거나 복사하지 않습니다.** 어디에 있는지 목록만 만듭니다.

### 1. 대시보드에서 바로 만들기 (권장 — 작업 스케줄러 필요 없음)

```
대시보드 → 🗂️ NAS 자료 → [🔎 지금 파일 목록 만들기]
```

훑을 폴더를 물어본 뒤 바로 시작하고, **진행 상황을 화면에 보여줍니다.**

```
⏳ 목록 만드는 중                                      42초  [중단]
   찾은 파일        18,420개
   훑은 폴더           612개
   /volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/…
```

- 몇 초씩 나눠 훑기 때문에 파일이 수만 개라도 **시간 초과로 끊기지 않습니다**
- 다 되면 폴더가 바로 뜨고, 브랜드에도 자동으로 붙습니다
- **다 될 때까지 창을 닫지 마세요** (닫으면 중간에 멈춥니다. 다시 누르면 처음부터 다시 합니다)
- 읽기만 하며 파일을 옮기거나 고치지 않습니다

**PHP가 공유폴더를 못 읽게 막혀 있으면 (가장 흔한 원인):**

```
PHP 가 공유폴더를 읽지 못하도록 막혀 있습니다.

DSM → 웹 스테이션 → 스크립트 언어 설정 → 쓰고 계신 PHP 프로필 → 편집 →
"open_basedir" 칸에 아래 경로를 추가하고 저장해 주세요.

    /volume1/넷폼알앤디 공유폴더
```

시놀로지 웹 스테이션은 기본적으로 PHP가 **웹 폴더 밖을 못 보게** 묶어둡니다
(`open_basedir`). 공유폴더를 읽으려면 그 경로를 허용 목록에 넣어야 합니다.
여러 경로는 콜론(`:`)으로 이어 씁니다.

```
/volume1/web:/volume1/넷폼알앤디 공유폴더
```

저장한 뒤 웹 스테이션이 다시 시작될 때까지 10~20초 기다렸다가 다시 눌러보세요.

**공유폴더 읽기 권한 주기 (가장 흔한 막힘)**

웹 서버는 **`http`** 라는 계정으로 돌아갑니다. 이 계정에 읽기 권한이 없으면
아무리 사장님 계정에 권한을 줘도 대시보드는 폴더를 못 읽습니다.

⚠️ 시놀로지는 권한 화면이 **두 곳**인데, `http` 계정은 아래 화면에서만 보입니다.

```
DSM → 제어판 → 공유 폴더 → 그 폴더 선택 → [편집] → [권한] 탭
  1. 화면 위 드롭다운을 "로컬 사용자" → "시스템 내부 사용자" 로 바꿉니다
  2. 목록에서 http 를 찾아 "읽기 전용" 에 체크합니다
  3. 저장
```

File Station → 속성 → 권한 에서 주는 것만으로는 안 되는 경우가 많습니다.
공유 폴더 자체의 권한을 위 화면에서 주셔야 합니다.

지금 웹 서버가 어떤 계정으로 도는지는 아래에서 확인할 수 있습니다.

```
http://192.168.0.37/brand/nasfiles.php?action=check
```
→ `"웹서버계정": "http"`

**폴더 접근 권한이 없으면 이렇게 알려줍니다:**

```
이 폴더를 읽을 권한이 없습니다: /volume1/넷폼알앤디 공유폴더

File Station 에서 이 공유폴더를 오른쪽 클릭 → 속성 → 권한 에서
"http" 사용자에게 읽기 권한을 주고, "하위 폴더에 적용" 을 체크해 주세요.
```

### 2. (선택) 매일 밤 자동으로 갱신하기

한 번 만들어두면 그 상태로 계속 쓸 수 있지만, 새로 올라오는 파일까지
자동으로 따라가려면 작업 스케줄러에 등록해 두시면 됩니다.

```
DSM → 제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트
```

| 항목 | 값 |
|---|---|
| 작업 이름 | `NAS 파일 목록 만들기` |
| 사용자 | `root` |
| 일정 | 매일 새벽 (예: 03:00) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/scan.sh` |

`scan.sh` 는 대시보드에서 정한 폴더(`data/scanroot.txt`)를 그대로 씁니다.

### 3. 확인

```
http://192.168.0.37/brand/nasfiles.php?action=check
```

`"파일수"` 에 숫자가 찍히면 성공입니다.

## 📣 채널 새 글 자동으로 받아오기

블로그·유튜브는 "새 글 올라갔어요" 하고 알려주는 구조가 아닙니다.
누군가 **가서 확인**해야 합니다. 그 일을 NAS 가 대신하게 해두는 것입니다.

등록해 두면 이렇게 됩니다.

| | 등록 전 | 등록 후 |
|---|---|---|
| 새 글 확인 시점 | 대시보드를 켜 뒀을 때만 | NAS 가 30분마다 미리 |
| 채널 탭 여는 속도 | 몇 초 기다림 | 바로 뜸 |
| 새 글 표시 | 없음 | 홈·왼쪽 목록에 빨간 숫자 |

### 등록하는 법

```
DSM → 제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트
```

| 항목 | 값 |
|---|---|
| 작업 이름 | `브랜드 채널 새 글 확인` |
| 사용자 | `root` |
| 일정 | 매일 · 반복 `30분` (원하시는 간격으로) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/feeds.sh` |

만들고 나서 목록에서 선택 → **[실행]** 을 눌러 한 번 돌려보세요.

### 확인

```
http://192.168.0.37/brand/channels.php?action=summary
```

`"자동확인"` 에 시각이 찍혀 있으면 잘 돌고 있는 것입니다.
대시보드 채널 탭에도 `NAS가 마지막으로 돌아본 때` 로 표시됩니다.

### 등록 안 해도 되나요

돌아가긴 합니다. **대시보드를 열어두는 동안에는** 30분마다 알아서 새로 받아옵니다.
다만 아무도 대시보드를 안 켜 둔 동안에는 확인하지 않습니다.

| | 예약 작업 등록 안 함 | 등록함 |
|---|---|---|
| 대시보드를 켜 뒀을 때 | 30분마다 확인 | 30분마다 확인 |
| 아무도 안 켰을 때 | 확인 안 함 | **계속 확인** |
| 아침에 처음 열었을 때 | 그때 받아오느라 몇 초 걸림 | 이미 받아둬서 바로 뜸 |

지금 어느 쪽인지는 **채널 탭 맨 위 안내 상자**가 알려줍니다.
🕒 노란 상자면 등록 안 된 것, ✅ 초록 상자면 등록된 것입니다.

`[↻ 전부 새로 받기]` 를 누르면 언제든 즉시 다시 받아옵니다.

> 여러 사람이 대시보드를 동시에 열어도 NAS 는 한 번만 나갑니다.
> (마지막으로 확인한 지 30분이 안 지났으면 그냥 넘어갑니다)

### 예약 작업을 걸었는데도 안 되는 것 같으면

`feeds.sh` 는 두 가지 방법을 차례로 시도합니다.

1. 명령줄 PHP 로 직접 실행 — 주소를 몰라도 되어 가장 확실합니다
2. 안 되면 웹 주소로 호출 (`http://localhost/브랜드폴더이름/channels.php`)

둘 다 실패하면 `/volume1/web/brand/feeds.log` 에 시도한 주소와 이유가 남습니다.
웹 주소가 다르면 `feeds.sh` 위쪽의 `URL=` 에 직접 넣어주세요.

### 새 글 표시(빨간 숫자)는 어떻게 정해지나요

**보는 사람마다 따로** 계산됩니다. 내가 마지막으로 채널 탭을 연 시점보다
뒤에 올라온 글만 새 글로 칩니다. 이 기록은 그 사람 브라우저에만 남고
NAS 에 저장되지 않아서, 다른 팀원의 표시에는 영향을 주지 않습니다.
채널 탭을 열면 그 브랜드의 새 글 표시는 사라집니다.
`"훑은폴더": "기록 없음"` 이면 아직 한 번도 성공하지 못한 것입니다.

### 새 파일은 자동으로 보이나요?

**폴더를 열어볼 때는 자동입니다.** 대시보드가 그 폴더의 디스크를 직접 읽기 때문에,
다른 직원이 방금 올린 파일도 **새로고침만 하면 바로** 보입니다. 목록을 다시 만들 필요가 없습니다.

**자동이 아닌 곳은 두 군데입니다.**

| 기능 | 새 파일 반영 |
|---|---|
| 폴더 열어보기 · 사진 보기 · 내려받기 | 🟢 바로 (새로고침) |
| 🔍 이름으로 찾기 | 🔴 목록을 다시 만들어야 함 |
| 🪄 브랜드 자동 연결 | 🔴 목록을 다시 만들어야 함 |

찾기와 자동 연결은 **미리 만들어 둔 목록**을 봅니다. 수만 개 파일을 매번 훑으면
느리기 때문입니다. 새 폴더가 생겼거나 검색에 안 잡히면
🗂️ NAS 자료 → **[🔎 목록 다시 만들기]** 를 한 번 눌러 주세요.

매일 밤 자동으로 갱신하려면 아래 "(선택) 매일 밤 자동으로 갱신하기" 를 보세요.

### 폴더 그대로 열어보기 (탐색기처럼)

대시보드 왼쪽 **🗂️ NAS 자료** 를 열면, 공유폴더가 **정리된 폴더 구조 그대로** 보입니다.
폴더를 눌러 타고 들어가고, 파일 옆 **[⬇]** 를 누르면 바로 내려받습니다.

```
🗂️ NAS 자료

[📁 폴더로 보기] [🔍 이름으로 찾기] [⚙️ 훑을 폴더 바꾸기]      12,480개 파일

[⬆ 상위 폴더] [↻ 새로고침] [📋 폴더 경로] [＋ 브랜드에 연결]   폴더 아래 전체 1,204개

🏠 00. 브랜드 공유폴더 › 공법

  📁 카탈로그          212개 · 1.4 GB      📁 시공사례        640개 · 8.1 GB
  📁 제안서            340개 · 2.2 GB

  📘 공법 개요.docx                       88 KB · 2026-08-20   [⬇]
```

- **🏠 이나 폴더 이름** 을 누르면 그 단계로 바로 되돌아갑니다
- **[🔍 이름으로 찾기]** 로 찾은 결과에서 **[📁 이 폴더 열기]** 를 누르면 그 파일이 있는 폴더가 열립니다
- 한 폴더에 파일이 500개를 넘으면 500개까지만 보여줍니다. 그 위는 이름으로 찾아주세요

### 브랜드 자동 연결 — 손으로 지정할 필요 없습니다

목록만 한 번 만들어두면, **폴더 이름과 브랜드 이름을 맞춰봐서 저절로 연결**됩니다.
브랜드마다 폴더를 지정해 주실 필요가 없습니다.

```
🗂️ NAS 자료 → 🪄 브랜드 자동 연결

  🧱 POUR공법          🪄 공법 · 1,204개
  🏢 아파트스퀘어        🪄 아파트스퀘어 · 860개
  ⚙️ POUR 솔루션        🪄 솔루션 · 412개
  🏘️ 단지온            🪄 단지온 · 96개

  어느 브랜드에도 안 붙은 폴더 — #_마케팅팀
```

- `공법` → **POUR공법**, `솔루션` → **POUR 솔루션** 처럼 앞뒤 말이 붙어 있어도 알아봅니다
- 폴더 이름 앞의 번호(`00.`)와 기호(`#_`), 띄어쓰기는 무시하고 비교합니다
- 브랜드를 새로 추가하면 **이름이 맞는 폴더가 저절로 붙습니다**
- 폴더 이름이 브랜드 이름과 많이 다르면 안 붙습니다 → 아래 "직접 연결" 을 쓰시면 됩니다
- 잘못 붙은 폴더는 그 브랜드 📁 자료 탭에서 **[숨기기]** 로 뺄 수 있습니다

### 직접 연결하고 싶을 때

찾는 것에서 끝나지 않고, **브랜드 자료 탭에 폴더를 연결해두면** 거기서 바로 열어보고 내려받을 수 있습니다.
**파일을 옮기거나 복사하지 않습니다.** 있는 자리에서 그대로 내보냅니다.

자동으로 안 붙는 폴더는 이렇게 붙이시면 됩니다.

방법 1 — 🗂️ NAS 자료에서 그 폴더까지 들어간 뒤 **[＋ 브랜드에 연결]**
방법 2 — 브랜드 → 📁 자료 탭 → **[📂 NAS 폴더 직접 연결]** 에 경로 붙여넣기

```
📁 자료 탭

📂 공법 공유폴더                    [🔍 폴더 안에서 찾기] [연결 해제]
   /volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/00. 브랜드 공유폴더/공법

   [↻ 새로고침] [📋 폴더 경로]                     폴더 아래 전체 1,204개
   🏠 공법 › 카탈로그

     📕 POUR공법 카탈로그.pdf        1.2 MB · 2026-08-28   [⬇]
     📕 방수 소개서.pdf              880 KB · 2026-08-20   [⬇]
```

- 연결한 폴더 **안쪽까지 타고 들어갈 수 있고**, 연결한 폴더보다 위로는 올라가지 않습니다
- 파일이 많으면 **[🔍 폴더 안에서 찾기]** 로 하위 폴더까지 한 번에 훑어 좁힐 수 있습니다 (조건은 저장됩니다)
- **연결 해제해도 NAS의 실제 파일은 그대로** 남습니다. 목록에서만 사라집니다
- 탐색기 형식(`\\netformrnd\...`)으로 붙여넣어도 알아서 변환합니다

### 훑을 폴더 바꾸기

목록을 만들 **최상위 폴더**를 바꾸려면 대시보드에서 하면 됩니다.

```
🗂️ NAS 자료 → [⚙️ 훑을 폴더 바꾸기] → 경로 입력
```

**탐색기 주소창에서 복사한 그대로 붙여넣으시면 됩니다.** 아래 세 형태를 모두 알아듣습니다.

```
Y:\넷폼알앤디 공유폴더\마케팅 공유폴더 외장하드 백업\00. 브랜드 공유폴더
\\netformrnd\넷폼알앤디 공유폴더\마케팅 공유폴더 외장하드 백업\00. 브랜드 공유폴더
/volume1/넷폼알앤디 공유폴더/마케팅 공유폴더 외장하드 백업/00. 브랜드 공유폴더
```

폴더 이름의 **띄어쓰기 · 점(`.`) · `#`** 은 그대로 두셔도 됩니다
(`00. 브랜드 공유폴더`, `#_마케팅팀` 모두 그대로 넣으시면 됩니다).
경로를 못 찾으면 **어떤 경로들을 찾아봤는지** 창에 그대로 보여드립니다.

> 시놀로지가 만드는 `#recycle`(휴지통)과 `@eaDir`(썸네일)만 목록에서 빠집니다.
> `#` 으로 시작하는 사장님 폴더는 빠지지 않습니다.

바꾼 값은 `data/scanroot.txt` 에 저장되며, **자동 업데이트로 덮어써지지 않습니다.**
바꾼 뒤에는 **작업 스케줄러에서 `scan.sh` 를 한 번 더 실행**해야 새 목록이 만들어집니다.

> 폴더를 좁힐수록 목록 만드는 시간이 짧아지고 화면도 깔끔해집니다.
> 브랜드 자료만 쓸 거라면 `00. 브랜드 공유폴더` 로 좁히는 쪽을 권합니다.

### 안전장치

- **읽기만 합니다.** 파일을 옮기거나 고치거나 지우지 않습니다
- 목록을 새로 만들다 실패하면 **기존 목록을 그대로 둡니다**
- 시놀로지가 만드는 `@eaDir`, `#recycle`, `.DS_Store` 는 목록에서 제외
- 검색 결과에서 **경로 복사** → 탐색기 주소창에 붙여넣으면 바로 열립니다
  (`\\netformrnd\넷폼알앤디 공유폴더\...` 형태로 변환해 줍니다)

## 파일이 빠졌거나 꼬였을 때 — 복구 주소

`save.php` 하나만 살아 있으면, 나머지 파일을 스스로 받아옵니다.

```
http://192.168.0.37/brand/save.php?action=bootstrap
```

브라우저로 이 주소를 열면 `brand.html`, `load.php`, `files.php`, `deploy.sh` 를
GitHub에서 직접 받아 제자리에 놓습니다. 결과가 이렇게 나오면 성공입니다.

```json
{ "ok": true, "결과": { "brand.html": "설치 완료", "deploy.sh": "설치 완료" } }
```

이미 최신이면 `"이미 최신"` 으로 표시되고 아무것도 바꾸지 않습니다.
**파일을 손으로 옮길 일이 없도록** 만들어 둔 장치이니, 뭔가 꼬이면 이 주소부터 열어보세요.

## ⚠️ 파일 업로드 용량 한도 올리기 (자료 탭을 쓰려면 필수)

PHP는 기본값이 **업로드 2MB / 요청 8MB** 로 매우 작습니다.
이 상태로는 카탈로그 PDF 하나도 못 올립니다. **한 번만 올려두면 됩니다.**

### 지금 한도 확인
```
http://192.168.0.37/brand/files.php?action=check
```
`"php업로드한도": "2M"` 처럼 나오면 아래대로 바꾸세요.

### 바꾸는 법
1. **Web Station → 스크립트 언어 설정 → PHP 탭**
2. `Default Profile` 선택 → **편집**
3. **「코어」 탭** 으로 이동
4. 아래 두 값을 찾아 수정

| 항목 | 권장값 |
|---|---|
| `upload_max_filesize` | `200M` |
| `post_max_size` | `210M` |

> `post_max_size`는 `upload_max_filesize`보다 **조금 더 크게** 잡아야 합니다.
> 파일 외에 다른 정보도 같이 전송되기 때문입니다.

5. **저장** → 위 확인 주소를 다시 열어 `200M` 으로 바뀌었는지 확인

`memory_limit`이 `256M` 이상인지도 함께 봐두면 좋습니다.

## (선택) 자동 업데이트 — 파일 복사를 아예 없애기

수정할 때마다 파일을 옮기는 게 번거로우면, **NAS가 스스로 최신 파일을 받아오게** 할 수 있습니다.
한 번만 설정하면 그 뒤로는 손댈 일이 없습니다.

```
Claude가 수정 → GitHub에 올림 → NAS가 정해진 시간에 자동으로 받아옴 → 새로고침만
```

### 설정 방법 (10분, 한 번만)

**1.** `deploy.sh` 파일을 NAS의 `web/brand/` 폴더에 올립니다 (다른 파일과 같은 위치)

**2.** DSM → **제어판** → **작업 스케줄러** → **생성** → **예약된 작업** → **사용자 정의 스크립트**

**3.** 아래처럼 설정합니다

| 항목 | 값 |
|---|---|
| 작업 이름 | `브랜드 대시보드 업데이트` |
| 사용자 | `root` |
| 일정 | 매일 / 원하는 시간 (또는 몇 시간마다) |
| 사용자 정의 스크립트 | `sh /volume1/web/brand/deploy.sh` |

**4.** 만든 작업을 선택하고 **실행** 버튼으로 한 번 돌려봅니다.
`web/brand/deploy.log` 파일에 `갱신: brand.html` 같은 기록이 남으면 성공입니다.

### 스크립트 스스로 최신화됩니다

`deploy.sh` 자체가 바뀌어도 다음 실행 때 자동으로 새 버전으로 교체됩니다.
**처음 한 번만** NAS에 올려두면, 이후로는 손댈 일이 없습니다.

### 이 스크립트의 안전장치

파일을 자동으로 덮어쓰는 일이라, 아래를 확인한 뒤에만 교체합니다.

- 내려받은 파일이 **비어 있거나 깨져 있으면 교체하지 않고** 기존 파일을 그대로 둡니다
- **내용이 바뀐 파일만** 교체합니다 (매번 덮어쓰지 않음)
- `data/` 폴더(입력한 숫자)는 **절대 건드리지 않습니다**
- 네트워크 오류로 실패해도 기존 화면은 멀쩡히 동작합니다

### 주의

자동이라는 건 **검토 없이 반영된다는 뜻**이기도 합니다.
급하게 확인이 필요한 변경이라면 자동 실행을 기다리지 말고,
작업 스케줄러에서 **[실행]** 버튼을 눌러 즉시 반영하세요.

## 인터넷 없는 사내망에서 차트 보이게 하기

회사 네트워크가 외부 인터넷을 막아둔 경우, 그래프 자리에
"차트 라이브러리를 불러오지 못했습니다"라고 뜹니다. **숫자와 표는 정상 동작**하며,
그래프만 안 보이는 상태입니다. 아래처럼 고칩니다.

1. 인터넷이 되는 PC에서 이 주소를 엽니다:
   `https://cdn.jsdelivr.net/npm/chart.js@4/dist/chart.umd.min.js`
2. `Ctrl+S`로 파일을 저장합니다.
3. 파일 이름을 정확히 **`chart.umd.min.js`** 로 바꿉니다.
4. NAS의 `web/brand/` 안에 **`vendor`** 폴더를 만들고 그 안에 넣습니다.

```
web/brand/
├── brand.html
├── load.php
├── save.php
└── vendor/
    └── chart.umd.min.js
```

새로고침하면 그래프가 나옵니다. (이후로는 인터넷 없이도 계속 동작합니다)

## 백업 — 꼭 해두세요

NAS 연결 후에는 `data/brand-data.json` **파일 하나가 유일한 원본**입니다.
이게 사라지면 데이터도 사라집니다.

- `save.php`가 **하루에 한 번 자동 백업**을 만듭니다 (`data/backup-2026-08-31.json`)
- 여기에 더해, NAS 관리자 화면에서 `web` 폴더에 대해
  **스냅샷(Snapshot Replication)** 또는 **Hyper Backup**을 켜두시길 권합니다.
- 중요한 시점에는 대시보드의 **[📤 내보내기]** 버튼으로 내 PC에도 한 부 받아두세요.

## 자주 겪는 문제

### 화면에 시놀로지 오류 페이지(HTML)가 나올 때

웹 스테이션은 **200 이 아닌 응답의 내용을 자기 오류 페이지로 바꿔치기** 합니다.
그래서 "권한 없음(403)", "폴더 없음(404)" 같은 진짜 이유가 화면에 닿지 못하고
`<!DOCTYPE html>` 로 시작하는 시놀로지 페이지만 보였습니다.

지금은 **모든 응답을 200 으로 보내고, 실패 여부는 JSON 안의 `ok` 로만** 알립니다.
원래 상태 코드는 `status` 값으로 함께 담깁니다.

> 새 PHP 파일을 만드실 일이 있으면 `http_response_code()` 로 오류 코드를 보내지 마세요.
> 내용이 통째로 버려집니다.


**Q. 접속하면 화면 대신 코드 글자가 잔뜩 나옵니다**
→ PHP가 안 켜진 상태입니다. 1단계에서 PHP 설치와 Web Station 설정을 다시 확인하세요.

**Q. 화면은 잘 열리는데 저장만 실패합니다** ← 가장 흔한 문제
→ `http` 계정의 쓰기 권한이 없는 경우입니다. 먼저 원인을 확인하세요.

```
http://192.168.0.37/brand/save.php?check=1
```

`"현재폴더_쓰기가능": "아니오"` 로 나오면 확정입니다. 이렇게 고칩니다.

1. File Station → **`web` 폴더** 우클릭 → 속성 → **권한** 탭
2. `http` 항목 선택 → 편집 (없으면 **생성** → 필터 아이콘 → **시스템 내부 사용자** → `http`)
3. **읽기 + 쓰기 전체 체크**
4. **「이 폴더, 하위 폴더 및 파일에 적용」 체크** ← 이게 핵심
5. 저장 후 위 주소를 다시 열어 `"예"` 로 바뀌었는지 확인

그래도 `"아니오"` 면 폴더 권한이 꼬인 것이니, `brand` 폴더를 지우고
**File Station으로 다시 만든 뒤** 파일을 올리세요.

**Q. "NAS 저장 실패 (404)"가 뜹니다**
→ `save.php`가 `brand.html`과 다른 폴더에 있습니다. 같은 폴더로 옮기세요.

**Q. 두 사람이 동시에 저장하면 어떻게 되나요?**
→ 파일이 깨지지는 않습니다(잠금 처리됨). 다만 **나중에 저장한 사람의 값이 남습니다.**
   같은 달 같은 브랜드를 동시에 편집하는 일은 피해 주세요.

**Q. 지금 우리 NAS가 인터넷에 열려 있는 상태인가요?**
→ `netformrnd.synology.me`라는 DDNS 주소로 접속이 되고 있다면,
   **WebDAV 포트(5006)가 외부 인터넷에 열려 있을 가능성이 높습니다.**
   DSM → **제어판 → 외부 액세스 → 라우터 구성**에서 어떤 포트가 열려 있는지 한번 확인해 보세요.
   쓰지 않는 포트가 열려 있다면 닫는 편이 안전합니다.
   또한 **제어판 → 보안 → 계정**에서 자동 차단(로그인 실패 시 IP 차단)을 켜두시길 권합니다.

**Q. 외부(집)에서도 보고 싶습니다**
→ 지금 설정은 **사내망 전용**입니다. 외부 공개는 보안 설정(HTTPS, 방화벽, 계정 권한)이
   추가로 필요하니, 필요해지면 그때 따로 안내해 드리겠습니다.
   **NAS를 아무 설정 없이 인터넷에 열어두면 위험합니다.**
