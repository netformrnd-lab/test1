# 📌 바뀌지 않는 주소 만들기

`trycloudflare.com` 주소가 끊긴 뒤에 쓰는 안내입니다.

---

## 먼저 알아야 할 것

**끊긴 그 주소(`facilities-literary-drag-burton...`)는 되살릴 수 없습니다.**

trycloudflare 주소는 Cloudflare 가 터널을 켤 때마다 **무작위로 던져 주는 이름**입니다.
- 이름을 골라서 받는 설정이 없습니다
- 터널이 꺼지면 그 이름은 사라집니다 (남에게 다시 배정될 수도 있습니다)
- 다시 켜면 **전혀 다른 이름**이 나옵니다

고정으로 바꾸는 설정은 **존재하지 않습니다.** 임시로 쓰라고 만든 것입니다.

---

## 쓸 수 있는 길은 둘

| | 비용 | 공유기 포트 | 주소 |
|---|---|---|---|
| **① NAS 주소 쓰기** (추천) | 무료 | 443 하나 열기 | `https://netformrnd.synology.me/brand/brand.html` |
| ② Cloudflare 고정 터널 | 도메인값 연 1~2만원 | 안 열어도 됨 | `https://brand.회사도메인.com/brand.html` |

- **사무실 안에서만 쓰신다면** 둘 다 필요 없습니다 — `http://192.168.0.37/brand/brand.html`
- **①이 기본**입니다. 이미 가지고 계신 주소라 새로 살 것도, 계정 만들 것도 없습니다
- **공유기를 못 건드리는 사정이 있으면** ②로 갑니다. 도메인을 하나 사야 합니다

---

## ① NAS 주소로 고정하기 (무료)

### 0. 지금 어디까지 돼 있는지 보기

DSM → 제어판 → **터미널 및 SNMP** → `SSH 서비스 활성화` 체크 → 적용.
그 다음 사무실 PC 에서 (명령 프롬프트 · 터미널):

```
ssh 관리자아이디@192.168.0.37
sudo sh /volume1/web/brand/fixed-url-check.sh
```

① ~ ⑥ 을 차례로 보고 **무엇이 모자란지 ❌ 로 짚어 줍니다.**
아래 1~3 중에 이미 된 것은 건너뛰시면 됩니다.

### 1. DDNS 가 우리를 가리키게

DSM → 제어판 → **외부 액세스** → **DDNS** 탭
- `netformrnd.synology.me` 줄을 고르고 **[지금 업데이트]**
- 「정상」 으로 바뀌면 됩니다

### 2. 인증서 받기 — ⚠️ **이걸 안 하면 보안 경고가 뜹니다**

> **「이 사이트에 대한 연결이 안전하지 않습니다」** 가 뜨는 까닭이 이것입니다.
>
> 인증서가 없으면 브라우저는 **자물쇠가 안 걸렸다**고 봅니다. 그 상태에서는
> 로그인할 때 적은 **아이디와 비밀번호가 글자 그대로 흘러갑니다.** 같은
> 와이파이에 있는 사람이 그대로 읽을 수 있습니다.
>
> 끊긴 trycloudflare 주소에서는 이 경고가 안 떴습니다 — Cloudflare 가
> 자기 인증서로 자물쇠를 대신 걸어 줬기 때문입니다. 이제 그 길이 없어졌으니
> **우리 인증서를 직접 받아야** 합니다. 무료고 5 분이면 됩니다.
>
> 경고가 떠도 「그냥 열기」 를 누르지 마세요. 한 번 누르면 브라우저가 기억해서
> 다음부터 경고를 숨깁니다 — 위험한 상태인데 안 보이게 됩니다.
> (이미 누르셨으면 아래 **2-4** 로 되돌립니다)


DSM → 제어판 → **보안** → **인증서** → **[추가]**
- `새 인증서 추가` → `Let's Encrypt 에서 인증서 가져오기`
- 도메인 이름: `netformrnd.synology.me`
- 전자 메일: 회사 메일
- **[완료]** (몇 분 걸립니다)

> ⚠️ 이 단계는 **아래 3번(포트 열기)이 먼저 돼 있어야** 성공합니다.
> Let's Encrypt 가 80 번 포트로 우리를 확인하기 때문입니다.
> 순서는 **3 → 2** 가 편합니다.

#### 2-2. 받은 인증서를 그 주소에 붙이기

인증서를 받았다고 끝이 아닙니다. **어느 주소에 쓸지 정해 줘야** 합니다.

DSM → 제어판 → **보안** → **인증서** → **[설정]**
- `netformrnd.synology.me` 줄의 인증서를 방금 받은 것으로 고릅니다
- **[확인]**

#### 2-3. http 로 들어와도 https 로 보내기

주소창에 `http://` 로 쳐도 자물쇠 걸린 쪽으로 넘겨 줍니다.

DSM → 제어판 → **로그인 포털** → **고급** 탭 (또는 Web Station → 웹 서비스 포털)
- **`HTTPS 연결로 자동 리디렉션`** 체크 → 적용

#### 2-4. 브라우저에 남은 「그냥 열기」 지우기

경고를 한 번 넘기면 크롬이 기억합니다. 고친 뒤에는 되돌려 주세요.
- 사진에 보이는 **[경고 켜기]** 를 누르면 바로 지워집니다
- 또는 주소창 자물쇠 → `사이트 설정` → **[데이터 삭제]**

그 뒤 새로 고쳐서 **자물쇠가 잠긴 모양**으로 보이면 끝났습니다.

### 3. 공유기에서 길 열기 (포트포워딩)

공유기 설정 화면에 들어가 **포트포워딩**(또는 `포트 전달` · `가상 서버` · `NAT`) 에서:

| 바깥 포트 | 보낼 곳 | 보낼 포트 |
|---|---|---|
| 443 | `192.168.0.37` | 443 |
| 80 | `192.168.0.37` | 80 |

- 80 은 **인증서 받을 때만** 쓰므로, 2번이 끝나면 닫아도 됩니다
- 공유기 기종을 알려 주시면 그 기종 화면에 맞춰 짚어 드립니다

### 4. 확인

**휴대폰에서 와이파이를 끄고**(LTE 로) 아래를 열어 봅니다:

```
https://netformrnd.synology.me/brand/brand.html
```

열리면 끝입니다. 이 주소는 **다시 바뀌지 않습니다.**

### 5. 옛 터널 끄기

`fixed-url-check.sh` 의 ⑥ 에 `cloudflared 가 돌고 있습니다` 라고 나오면 꺼 주세요.
안 꺼도 해는 없지만, **아무나 들어올 수 있는 길**을 하나 더 열어 두는 셈입니다.

## ② Cloudflare 고정 터널 (도메인 필요)

공유기를 못 건드릴 때만 이 길로 갑니다.

### 1. 도메인 준비

Cloudflare 계정을 만들고 (무료), **Cloudflare Registrar 에서 도메인을 삽니다**
(`.com` 연 1~2만원). 이미 회사 도메인이 있으면 Cloudflare 로 옮기면 됩니다.

> `cloudflare.com` 하위 주소는 **나눠 주지 않습니다.**
> 내 도메인이 Cloudflare 에 올라가 있어야 고정 터널이 됩니다.

### 2. NAS 에 cloudflared 넣고 터널 만들기

SSH 로 NAS 에 들어가서:

```sh
# ① 받기 (시놀로지는 대부분 amd64 입니다)
sudo mkdir -p /usr/local/bin
sudo wget -O /usr/local/bin/cloudflared \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
sudo chmod +x /usr/local/bin/cloudflared

# ② 로그인 — 나오는 주소를 브라우저로 열어 도메인을 고릅니다
sudo /usr/local/bin/cloudflared tunnel login

# ③ 터널 만들기 (이름은 아무거나, 한 번만)
sudo /usr/local/bin/cloudflared tunnel create brandhub

# ④ 주소 붙이기 — 여기서 정한 주소가 <<영구 고정>> 입니다
sudo /usr/local/bin/cloudflared tunnel route dns brandhub brand.회사도메인.com
```

### 3. 설정 파일

`/etc/cloudflared/config.yml` 을 이렇게 만듭니다
(`<터널ID>` 는 ③ 에서 찍혀 나온 값):

```yaml
tunnel: <터널ID>
credentials-file: /root/.cloudflared/<터널ID>.json
ingress:
  - hostname: brand.회사도메인.com
    service: http://127.0.0.1:80
  - service: http_status:404
```

### 4. 꺼지지 않게 (여기가 핵심)

터널이 꺼져서 주소가 끊긴 것이므로, **서비스로 등록해 저절로 다시 켜지게** 합니다.

```sh
sudo /usr/local/bin/cloudflared service install
sudo systemctl enable --now cloudflared    # systemd 가 없으면 아래로
```

systemd 가 없는 DSM 이면 **DSM → 제어판 → 작업 스케줄러** 에
`부팅 시` 트리거로 아래를 등록합니다:

```sh
/usr/local/bin/cloudflared --config /etc/cloudflared/config.yml tunnel run
```

### 5. 확인

```
https://brand.회사도메인.com/brand.html
```

이 주소는 NAS 를 재부팅해도, 터널이 한 번 꺼졌다 켜져도 **그대로입니다.**

## 어느 쪽이든 끝나면

- 직원들에게는 **그 주소 하나만** 알려 주면 됩니다 (다시 공유할 일 없음)
- 주소창에 **자물쇠가 잠겨 보이는지** 꼭 확인하세요.
  경고가 뜨는 상태면 비밀번호가 글자 그대로 흘러갑니다
- 대시보드 로그인 비밀번호(`brandhub2026` 기본값)를 **꼭 바꿔 주세요.**
  주소가 인터넷에 열리면 그 비밀번호가 유일한 자물쇠입니다
- 전에 경고를 넘기며 쓰던 동안 그 비밀번호가 새어 나갔을 수 있으니,
  **인증서를 붙인 뒤에 바꾸시는 것**이 순서입니다
