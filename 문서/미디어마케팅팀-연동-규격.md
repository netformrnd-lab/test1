# 미디어마케팅팀 TeamHub 와 주고받는 규격

미디어마케팅팀 프로그램 **`mediam_TeamHub.html` (v2.5.6)** 안을 직접 읽어서
확인한 것입니다. 추측이 아니라 그쪽 코드에 적혀 있는 그대로입니다.

---

## 1. 자리와 이름 — 이미 서로 맞습니다

| 무엇 | 자리 |
|---|---|
| 프로그램 | `Z:\넷폼알앤디 공유폴더\00. 미디어마케팅팀\미디어마케팅팀 브랜드허브\프로그램_미디어마케팅팀 브랜드허브\mediam_TeamHub.html` |
| 할 일 DB | `…\미디어마케팅팀 브랜드허브\DB_미디어마케팅팀 브랜드허브` |
| 그 옆 | `DB_backup` · `DB_Copy` |
| 할 일 파일 | `미디어마케팅팀-할일.json` (`.csv` 도 됩니다) |

- 할 일 파일은 **DB 폴더 바로 안**에 있을 수도 있고, **날짜 폴더**
  (`20261016` 같은) 안에 있을 수도 있습니다. 우리는 세 단계까지 훑으니
  어느 쪽이든 찾습니다.
- 우리가 못 박아 둔 값(`LK_DIG_DEF` · `LK_FILE_DEF`)과 똑같습니다.

---

## 2. 할 일 파일 모양

### 표(CSV) — 머리말이 **한글(영문)** 입니다

```
제목(title), 내용(description), 업무유형(task_type_id), 상태(status_id),
담당(assignee_id), 시작일(start_date), 마감일(due_date), 프로젝트(project_id),
우선순위(priority_id), 진척률(progress), 태그(tags)
```

우리가 받는 자리는 이렇게 맞춥니다 —

| 그쪽 | 우리 |
|---|---|
| 제목(title) | 할 일 이름 |
| 내용(description) | 메모 |
| 상태(status_id) | 상태 |
| 담당(assignee_id) | 담당 |
| 마감일(due_date) | 기한 |
| 진척률(progress) | 진척률 |

업무유형 · 시작일 · 프로젝트 · 우선순위 · 태그는 아직 안 씁니다.

### JSON

`{ schemaVersion, 생성일시, tasks:[ … ] }` 처럼 **한 겹 안**에 들어 있습니다.
우리는 한 겹 안까지 뒤져서 찾습니다.

### 조심할 것

- **담당이 번호로 올 수 있습니다** (`assignee_id: 7`). 그러면 명단으로
  가릴 수가 없으니, 가리지 않고 그대로 둡니다 — 버리는 것보다 낫습니다.
- **진척률 0 은 빈 칸이 아닙니다.** 아직 손 안 댄 일입니다.

## 3. 양쪽을 통째로 맞추는 길 (그쪽이 만들어 둔 것)

미디어마케팅팀 프로그램 안에 **「🔄 브랜드 허브 동기화」** 창이 따로
있습니다. 할 일뿐 아니라 프로젝트(보조 업무) · 루틴 · 일정 · KPI 까지
한 파일로 오갑니다. 차례는 이렇습니다 —

1. **브랜드허브** 오른쪽 위 **📤** → 파일 받기
2. **TeamHub** 에서 그 파일 고르고 미리보기 확인 → **[동기화]**
3. 받은 파일을 다시 **브랜드허브** **📥** 로 넣기
   (TeamHub 에서 바뀐 것이 있을 때만)

- 그쪽은 우리 파일을 **`schema === 2` 이고 `brands` 가 있는 것**으로
  알아봅니다. 우리 📤 가 내는 파일이 바로 그 모양입니다.
- 그쪽은 **`.json` 만** 받습니다 (csv 아님).
- 파일이 오래된 것이면 그쪽이 「방금 내보낸 파일을 쓰세요」 라고
  막아 줍니다.
- 3번은 **덮어쓰기**입니다. 그래서 우리 쪽에서 덮어쓰기 직전에
  `브랜드허브_되돌리기용_날짜_시각.json` 을 한 벌 받아 둡니다.
  잘못되면 그 파일을 다시 📥 로 넣으면 그대로 돌아옵니다.
